## 1. 뉴스 요약

웹이코노미(11-09)는 **성동구가 성수동 상권 빅데이터 분석으로 3년 연속 수상**했다고 보도했다. 상권 분석은 카드 매출, 유동인구, 점포 개·폐업, 임대료처럼 **서로 다른 기관·시스템에서 나온 데이터를 하나로 묶어** 지역·업종·시간대별로 잘라 보는 작업이다. 이런 분석을 반복적으로 빠르게 하려면, 데이터를 업무 처리용 DB가 아닌 **분석 전용 구조**로 모아 두는 것이 기본이다. 분석에 쓰인 데이터와 방법은 제목 이상으로 확인되지 않으므로, 이 글은 기사를 계기로 **데이터 웨어하우스와 OLAP**를 깊게 다루는 토픽 심화 글이다.

## 2. 핵심 개념

### 정의
**데이터 웨어하우스**(DW)는 여러 업무 시스템의 데이터를 **주제 중심으로 통합하고, 시간에 따른 이력을 보존하며, 변경하지 않고(비휘발성) 분석에 쓰도록** 저장한 의사결정 지원용 데이터베이스다(인몬의 정의: 주제 지향·통합·시계열·비휘발). **OLAP**(Online Analytical Processing)은 이 데이터를 **여러 차원(지역·업종·시간)으로 집계하고 잘라 보는** 다차원 분석 방식이다.

### 구성도 — 상권 분석 데이터 웨어하우스

```
 [원천 시스템]
  카드 매출 · 유동인구(통신) · 사업자 개·폐업 · 임대료 · 행정구역
        │
        ▼  ETL (추출 → 정제·표준화 → 적재)  / ELT (적재 후 변환)
 ┌───────────── 데이터 웨어하우스 ─────────────┐
 │  스테이징 → 통합 계층 → 차원 모델(스타 스키마) │
 │                                              │
 │        [지역 차원]   [시간 차원]               │
 │              \        /                       │
 │            [매출 사실 테이블] ── [업종 차원]    │
 │              (매출액, 건수)                    │
 └──────────────────────┬───────────────────────┘
                        ▼
 [데이터 마트]  상권 분석 마트 · 정책 평가 마트
                        ▼
 [OLAP·BI]  지역별·업종별·시간대별 대시보드, 드릴다운 분석
```

### OLTP vs OLAP

| 구분 | OLTP(업무 처리) | OLAP(분석) |
|---|---|---|
| 목적 | 거래 기록·처리 | 집계·추세 분석 |
| 사용자 | 현업 실무자·고객 | 분석가·의사결정자 |
| 질의 | 짧고 잦은 읽기·쓰기 | 길고 복잡한 집계 읽기 |
| 데이터 범위 | 현재 상태 | 과거 이력 포함 |
| 설계 | 정규화(중복 최소) | 비정규화·차원 모델(조회 성능) |
| 갱신 | 실시간 | 주기적 적재(배치·준실시간) |
| 성능 지표 | 초당 트랜잭션 수 | 질의 응답 시간 |

### 데이터 웨어하우스 구축 방식 — 인몬 vs 킴볼

| 구분 | 인몬(Top-down) | 킴볼(Bottom-up) |
|---|---|---|
| 순서 | 전사 DW 먼저 → 데이터 마트 파생 | 데이터 마트(차원 모델) 먼저 → 통합 |
| DW 모델링 | 정규화(3NF) | 차원 모델(스타 스키마) |
| 장점 | 전사 일관성, 단일 진실 원천 | 빠른 구축, 현업 이해 쉬움 |
| 단점 | 구축 기간·비용 큼 | 마트 간 불일치 위험(적합 차원으로 보완) |
| 적합 상황 | 대규모 전사 통합 | 부서·주제별 빠른 성과 |

### 스타 스키마 vs 스노우플레이크 스키마

| 구분 | 스타 스키마 | 스노우플레이크 스키마 |
|---|---|---|
| 차원 테이블 | 비정규화(한 테이블) | 정규화(여러 테이블로 분해) |
| 조인 수 | 적음 | 많음 |
| 조회 성능 | 빠름 | 상대적으로 느림 |
| 저장 공간 | 중복으로 큼 | 중복 감소 |
| 유지보수 | 차원 속성 변경 시 중복 갱신 | 갱신 쉬움 |

### OLAP 연산
- **롤업**(Roll-up): 상위 수준으로 집계(동 → 구 → 시)
- **드릴다운**(Drill-down): 하위 수준으로 상세화(월 → 일 → 시간대)
- **슬라이스**(Slice): 한 차원 값을 고정(2026년만)
- **다이스**(Dice): 여러 차원 범위를 동시에 제한(성수동 × 음식점 × 주말)
- **피벗**(Pivot): 행·열 축을 바꿔 보기

### 천천히 변하는 차원(SCD)
상권 분석에서는 **업종 분류·행정구역 경계가 바뀌는** 일이 생긴다. 과거 매출을 바뀐 기준으로 볼지, 당시 기준으로 볼지를 정하는 것이 SCD 설계다.
- **유형 1**: 덮어쓰기(이력 없음)
- **유형 2**: 새 행 추가 + 유효 기간 관리(이력 보존, 가장 많이 사용)
- **유형 3**: 이전 값 컬럼 추가(직전 값만 보존)

### 저장 방식 — MOLAP·ROLAP·HOLAP
- **MOLAP**: 다차원 큐브에 미리 집계해 저장 — 빠르지만 큐브 크기 증가
- **ROLAP**: 관계형 DB에서 SQL로 집계 — 확장성 높지만 느릴 수 있음
- **HOLAP**: 상세는 관계형, 요약은 큐브 — 두 방식 절충

## 4. 연결 기출 토픽과 예상 변형

- **데이터 레이크·스웜프**: 139회 2교시에 **데이터 레이크와 데이터 스웜프**가 출제됐다. 데이터 웨어하우스(정형·스키마 우선)와 데이터 레이크(원본·스키마 나중)를 비교하는 변형이 자연스럽다.
- **분산 DB**: 139회 1교시 **분산 DB 투명성**이 출제됐다. 대규모 DW는 분산·병렬 처리(MPP)로 구현되므로 함께 정리할 수 있다.
- **스토리지**: 140회 3교시 **스토리지 아키텍처 비교**(블록·파일·오브젝트)가 출제됐다. 레이크하우스 구조에서 DW 테이블이 오브젝트 스토리지 위에 놓이는 흐름과 연결된다.
- **예상 변형**
  - 1교시: "스타 스키마와 스노우플레이크 스키마를 비교하시오"
  - 1교시: "SCD(Slowly Changing Dimension)의 유형을 설명하시오"
  - 논술: "공공 빅데이터 분석을 위한 데이터 웨어하우스 구축 방안(모델링·ETL·OLAP)을 제시하시오"

## 5. 답안 구성 예시

**단답형**(1교시, 1페이지)
- 정의: 주제 지향·통합·시계열·비휘발 특성을 가진 의사결정 지원용 통합 데이터 저장소
- 특징 3개: ① OLTP와 분리된 분석 전용 구조 ② 사실·차원 테이블 기반 차원 모델 ③ OLAP 연산으로 다차원 분석
- 구성도 키워드: 원천 시스템 → ETL → DW(스타 스키마) → 데이터 마트 → OLAP·BI

**논술형(2~4교시) 목차**
1. 개요: 기관 간 데이터를 묶는 상권·정책 분석 수요와 DW의 필요성
2. 구성/비교: 상권 DW 구성도, OLTP vs OLAP, 인몬 vs 킴볼, 스타 vs 스노우플레이크 비교표
3. 적용방안: 지역·시간·업종 적합 차원 정의, SCD 유형 2로 경계 변경 이력 관리, 주제별 데이터 마트, 레이크하우스 연계
4. 고려사항: 원천 데이터 표준·코드 불일치, 개인정보(가명·집계), 갱신 주기, 차원 변경 관리
5. 기술사 제언: 부서별 마트를 따로 만들기 전에 **지역·시간·업종 같은 적합 차원을 먼저 표준화**해 마트 간 수치가 어긋나지 않게 하고, 원천 데이터는 집계·가명 단계에서만 결합할 것
