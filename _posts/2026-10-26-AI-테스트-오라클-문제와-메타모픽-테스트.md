## 1. 뉴스 요약

서울경제(10-23)는 "**AI 성능보다 업무 성과…기업 도입 확산 관건은 '신뢰'**"라는 제목으로, 기업이 AI를 도입할 때 벤치마크 점수보다 실제 업무에서 믿고 쓸 수 있는지를 더 중시한다는 흐름을 다뤘다. 같은 날 푸드투데이(10-23)는 **농협중앙회가 AI '환각' 차단 기술 등 5건의 특허를 출원**했다고 전했다. 두 기사 모두 "AI 결과가 맞는지 어떻게 확인할 것인가"라는 검증 문제로 이어지지만 세부 내용은 제목 이상으로 확인되지 않는다. 이 글은 140회에 출제된 **메타모픽 테스트**를 중심으로 AI 시스템 검증 기법을 깊게 다루는 **토픽 심화 글**이다.

## 2. 핵심 개념

### 정의
**테스트 오라클 문제**(Test Oracle Problem)는 테스트 실행 결과가 맞는지 판정할 **기대값(정답)을 정하기 어렵거나 비용이 너무 큰** 상황을 말한다. **메타모픽 테스트**(Metamorphic Testing)는 개별 출력의 정답 대신, **입력을 정해진 방식으로 바꿨을 때 출력 사이에 성립해야 하는 관계**(메타모픽 관계, MR)를 검사해 이 문제를 우회하는 테스트 기법이다.

### 오라클 문제가 생기는 대상

| 대상 | 오라클이 어려운 이유 | 메타모픽 관계 예시 |
|---|---|---|
| 과학·수치 계산 | 정답을 손으로 계산할 수 없음 | sin(x) = sin(π − x) |
| 검색 엔진 | 전체 정답 목록을 알 수 없음 | 검색 조건을 추가하면 결과는 기존 결과의 부분집합 |
| 이미지 분류 AI | 모든 입력의 정답 라벨 확보 불가 | 밝기를 조금 바꿔도 분류 결과 유지 |
| 기계번역 | 정답 번역이 여러 개 | 문장 내 고유명사만 바꾸면 나머지 번역 구조 유지 |
| LLM 질의응답 | 자유 서술형 출력 | 질문을 같은 뜻으로 바꿔 말해도 핵심 답 동일 |
| 추천 시스템 | "좋은 추천"의 기준이 주관적 | 사용자 이력 순서를 섞어도 결과 집합 동일(순서 무관 모델일 때) |

### 구성도 — 메타모픽 테스트 절차

```
 ① MR 식별      도메인 지식으로 "입력 변환 ↔ 출력 관계" 정의
       │          예) 질의 의미 보존 변환 → 핵심 답변 동일
       ▼
 ② 원본 테스트  원본 입력 x 준비 (기존 테스트 케이스 재사용 가능)
       │
       ▼
 ③ 후속 테스트  변환 함수 T 적용 → x' = T(x)
       │
       ▼
 ④ 실행         f(x), f(x') 실행
       │
       ▼
 ⑤ 관계 검사    R(f(x), f(x')) 성립 여부 판정
       │          └ 위반 → 결함 후보 (정답을 몰라도 "모순"은 확인 가능)
       ▼
 ⑥ 분석·축적    위반 사례 원인 분석 → MR·테스트셋 회귀 자산화
```

메타모픽 테스트가 잡는 것은 **오답 자체가 아니라 모순**이다. 두 출력이 모두 틀렸지만 관계는 지키는 경우는 놓칠 수 있으므로, 기대값 테스트·사람 검토와 함께 쓴다.

### 메타모픽 관계(MR) 유형

| 유형 | 관계 | 예시 |
|---|---|---|
| 불변(Invariance) | 변환해도 출력 동일 | 동의어 치환 후 감성 분류 동일 |
| 단조(Monotonic) | 입력 증가 시 출력도 증가/감소 | 대출 소득 증가 시 승인 점수 하락 없음 |
| 포함(Inclusion) | 결과가 부분/상위 집합 | 필터 추가 시 검색 결과 축소 |
| 역(Inverse) | 반대 변환 시 반대 결과 | 부정문으로 바꾸면 참/거짓 판정 반전 |
| 순열(Permutation) | 순서를 바꿔도 결과 동일 | 문서 순서 섞어도 요약 핵심 동일 |
| 가산(Additive) | 입력 결합 시 출력 결합 | 두 리스트 합의 합계 = 각 합계의 합 |

### 오라클 문제 대응 기법 비교

| 기법 | 판정 기준 | 장점 | 한계 |
|---|---|---|---|
| 기대값 비교 | 사전에 정한 정답 | 판정이 명확 | 정답 작성 비용, 생성형 출력에 부적합 |
| 메타모픽 테스트 | 출력 간 관계 | 정답 없이 대량 테스트 가능 | MR 설계에 도메인 지식 필요, 모순 아닌 오답은 놓침 |
| 차분 테스트(Differential) | 다른 구현과 결과 비교 | 기준 구현이 있으면 효과적 | 두 구현이 같은 오류를 내면 탐지 불가 |
| 속성 기반 테스트(PBT) | 출력이 만족할 일반 속성 | 무작위 입력 자동 생성 | 속성 정의가 약하면 결함 놓침 |
| LLM-as-a-Judge | 평가 모델의 판정 | 자유 서술형 평가 가능 | 평가 모델 자체의 편향·오류 |
| 사람 검토 | 전문가 판단 | 맥락·품질까지 판단 | 비용·처리량 한계, 일관성 문제 |

### 관련 표준·기준
- **ISO/IEC/IEEE 29119**: 소프트웨어 테스팅 국제표준 시리즈(개념·프로세스·문서·기법)
- **ISO/IEC TR 29119-11**: AI 기반 시스템 테스트 지침 — 오라클 문제와 메타모픽 테스트 등 AI 특화 기법을 다룸
- **ISO/IEC 25010 / 25059**: 소프트웨어 품질 모델 / AI 시스템 품질 모델(기능 정확성·견고성 등)

- 메타모픽 테스트의 장점과 한계(모순 탐지 vs 오답 탐지)
- 차분 테스트·속성 기반 테스트·LLM-as-a-Judge 비교

- 기대값 테스트·사람 검토와의 조합 전략

## 4. 연결 기출 토픽과 예상 변형

- **메타모픽 테스트**: 140회 3교시에 **메타모픽 테스트**가 직접 출제됐다. 블로그 140회 분석에서도 예측 카드가 놓친 문항으로 분류된 만큼, 같은 개념이 **AI·LLM 검증 맥락**으로 다시 나올 가능성이 있다.
- **테스트 기법 기본기**: 139회 3교시 **SW 테스트 7원리·동등분할·경계값 분석**이 출제됐다. 명세 기반 기법(동등분할·경계값)과 메타모픽 테스트를 "오라클 유무" 기준으로 비교하면 답안의 차별점이 된다.
- **품질 모델**: 140회 1교시 **ISO/IEC 25010 주특성·부특성**이 출제됐다. AI 시스템 품질 모델(25059)과 함께 정리해 두면 품질·테스트 문항을 묶어 대응할 수 있다.
- **예상 변형**
  - 1교시: "테스트 오라클 문제(Test Oracle Problem)와 해결 기법을 설명하시오"
  - 1교시: "메타모픽 관계(Metamorphic Relation)의 유형을 예시와 함께 설명하시오"
  - 논술: "생성형 AI 서비스의 품질 검증이 어려운 이유와 테스트 전략(메타모픽·차분·LLM 평가)을 논하시오"

## 5. 답안 구성 예시

**단답형**(1교시, 1페이지)
- 정의: 출력의 정답 대신 입력 변환에 따른 출력 간 관계(MR)를 검사해 오라클 문제를 우회하는 테스트 기법
- 특징 3개: ① 정답 없이 결함 탐지 ② 기존 테스트 케이스 재사용(후속 케이스 자동 생성) ③ 도메인 지식 기반 MR 설계
- 구성도 키워드: MR 식별 → 원본 x → 변환 x'=T(x) → 실행 f(x), f(x') → 관계 R 검사 → 위반 분석

**논술형(2~4교시) 목차**
1. 개요: AI·LLM 확산과 정답을 정하기 어려운 소프트웨어의 증가
2. 구성/비교: 메타모픽 테스트 절차 구성도, MR 유형표, 오라클 대응 기법 비교표
3. 적용방안: LLM 질의응답에 의미 보존·부정 변환 MR 적용, 위반 사례 회귀 자산화, CI 파이프라인 연동
4. 고려사항: MR의 결함 탐지력 편차, 모순 아닌 오답 미탐지, 생성 출력의 비결정성(샘플링)
5. 기술사 제언: 단일 기법에 의존하지 말고 **메타모픽 테스트로 대량 검증, LLM 평가로 서술 품질, 사람 검토로 고위험 판단**을 나누는 다층 검증 체계를 갖출 것
