## 1. 뉴스 요약

2026-06-08 넷앱(NetApp)과 레드햇(Red Hat)이 **대규모 가상머신(VM)과 컨테이너 환경의 데이터를 블록 단위 증분 백업으로 보호하는 기술 협력**을 발표했다고 보도됐다. 핵심은 ① VM과 컨테이너가 혼재하는 현대 인프라에서 **변경된 데이터 블록만 추적·백업(CBT, Changed Block Tracking)**해 백업 시간과 저장 공간을 크게 줄인다는 점, ② 가상화(VM)와 컨테이너(쿠버네티스)를 **하나의 데이터 보호 체계로 통합**한다는 점, ③ 대규모·고빈도 백업 환경에서 **백업 창(backup window) 단축과 복구 효율**을 동시에 달성한다는 점이다.

컨테이너로의 워크로드 이동, OpenShift Virtualization 같은 컨테이너 위 VM 운영이 확산되면서 **VM·컨테이너 통합 백업과 재해복구(DR)**는 시스템 인프라의 핵심 과제가 됐다. 백업 전략, 증분/차등 백업, RPO/RTO, DR은 기술사 시스템구조 영역의 단골 주제로, 구체적 기업 기술 협력이라는 시의성과 맞물려 출제 가치가 높다.

## 2. 핵심 개념

### CBT(Changed Block Tracking)와 블록 단위 증분 백업

CBT는 직전 백업 이후 **실제로 변경된 데이터 블록만 식별**하는 기술이다. 파일 전체나 디스크 전체를 다시 읽지 않고 변경 블록만 전송하므로, 백업 시간·네트워크 부하·저장 용량을 대폭 절감한다. 대규모 VM 팜에서 매일 전체 백업이 불가능한 환경에 필수적이다.

### 백업 유형 비교

- **전체 백업(Full)**: 전체 데이터 복제. 복구 단순하나 시간·용량 부담 큼
- **증분 백업(Incremental)**: 직전 백업 이후 변경분만. 백업 빠르나 복구 시 체인 의존
- **차등 백업(Differential)**: 마지막 전체 백업 이후 변경분 누적. 증분과 전체의 절충
- **합성 전체 백업(Synthetic Full)**: 기존 백업 데이터를 조합해 가상의 전체 백업 생성

### 스냅샷과 백업의 차이

- **스냅샷(Snapshot)**: 특정 시점 상태를 빠르게 보존. 원본 스토리지에 의존하며 단독으로는 재해 대비에 한계
- **백업(Backup)**: 별도 매체·위치에 독립 사본 저장. 원본 손실에도 복구 가능

### RPO와 RTO

- **RPO(Recovery Point Objective)**: 허용 가능한 데이터 손실 시점(얼마나 자주 백업할 것인가)
- **RTO(Recovery Time Objective)**: 허용 가능한 복구 소요 시간(얼마나 빨리 복구할 것인가)

증분 백업·CBT는 RPO를 짧게 가져가면서도 백업 부하를 낮추는 데 기여한다.

## 3. 기술사 출제 포인트

- 개념 정의와 필요성: CBT·블록 단위 증분 백업이 대규모 VM·컨테이너 환경에서 필요한 이유
- 기존 방식과의 비교: 전체/증분/차등/합성 전체 백업의 특성과 트레이드오프
- 스냅샷 vs 백업: 시점 보존과 독립 사본 보관의 차이, DR 관점의 한계
- 아키텍처 구성요소: 변경블록 추적, 백업 카탈로그, 중복제거(dedup)·압축, 오프사이트 복제
- 핵심 지표: RPO/RTO 정의와 백업 주기 설계에 미치는 영향
- VM·컨테이너 통합 보호: 가상화와 쿠버네티스(PV/스토리지)의 데이터 보호 통합 고려사항
- 도입 시 고려사항: 백업 창 단축, 복구 검증(restore test), 3-2-1 백업 원칙, 랜섬웨어 대비 불변 저장(immutable)
