## 1. 뉴스 요약

법률신문(10-20)은 "**허위 판례 인용-환각 줄었다**"는 제목으로, 법률 실무에서 문제가 됐던 생성형 AI의 **존재하지 않는 판례 인용**과 환각 현상이 줄어든 흐름을 다뤘다. 판례 번호·사건명처럼 형식은 그럴듯하지만 실재하지 않는 출처를 만들어내는 문제는, 법률처럼 **근거의 정확성이 곧 결과물의 가치**인 분야에서 가장 치명적인 AI 결함으로 꼽혀 왔다. 감소 원인이나 측정 방식은 제목 이상으로 확인되지 않으므로, 아래에서는 LLM 환각의 일반 구조와 완화·평가 방법을 답안 재료로 정리한다.

## 2. 핵심 개념

### 정의
**환각**(Hallucination)은 LLM이 입력·근거 자료나 실제 사실과 맞지 않는 내용을 **유창하고 확신 있는 형태로 생성**하는 현상이다. 모델이 사실을 조회하는 것이 아니라 **다음 토큰의 확률 분포에서 그럴듯한 문장을 생성**하기 때문에 구조적으로 발생하며, 미국 NIST의 생성형 AI 위험 프로파일(AI 600-1)은 이를 **작화**(Confabulation)라는 위험 항목으로 분류한다.

### 환각의 유형

| 구분 | 기준 | 예시(법률 맥락) |
|---|---|---|
| 내재적(Intrinsic) | 주어진 근거와 **모순** | 첨부 판결문의 결론을 반대로 요약 |
| 외재적(Extrinsic) | 근거로 **확인 불가**한 내용 추가 | 판결문에 없는 판시 이유를 덧붙임 |
| 사실성(Factuality) 오류 | 세계 지식과 불일치 | 폐지된 조문을 현행법으로 설명 |
| 충실성(Faithfulness) 오류 | 지시·문맥과 불일치 | 요청한 쟁점과 다른 쟁점을 답변 |
| 인용 날조 | 존재하지 않는 출처 생성 | 실재하지 않는 사건번호·판례 |
| 인용 오귀속 | 실재 출처에 다른 내용 귀속 | 실제 판례지만 판시 내용이 다름 |

인용 날조는 "출처 확인"으로 잡히지만, **인용 오귀속은 출처가 실재하므로 더 발견하기 어렵다**. 답안에서 두 가지를 구분해 쓰면 깊이가 드러난다.

### 구성도 — 환각 완화 다층 구조

```
 사용자 질의
     │
     ▼
 [1. 입력 단계]   질의 명확화 · 범위 제한 · 근거 필수 지시(하네스/프롬프트)
     │
     ▼
 [2. 검색 단계]   RAG: 하이브리드 검색(키워드+벡터) → 재순위화
     │            └ 신뢰 원천 한정(공식 판례 DB · 법령 DB)
     ▼
 [3. 생성 단계]   근거 기반 생성 · 근거 없으면 "확인 불가" 응답(거절)
     │            └ 인용은 검색 결과 ID에서만 선택(제약 생성)
     ▼
 [4. 검증 단계]   인용 실존 확인 → 인용-주장 일치 검사(NLI/LLM-Judge)
     │            └ 불일치 시 재생성 또는 해당 문장 삭제
     ▼
 [5. 사람 검토]   전문가 최종 확인(HITL) · 피드백 → 평가셋 축적
```

어느 한 단계로 환각을 0으로 만들 수는 없다. **검색으로 확률을 낮추고, 검증으로 잡아내고, 사람이 책임지는** 구조가 기본형이다.

### 완화 기법 비교

| 기법 | 작동 원리 | 효과 범위 | 한계 |
|---|---|---|---|
| RAG | 외부 근거를 문맥에 주입 | 외재적·사실성 오류 감소 | 검색 실패 시 오히려 오답 확신 |
| 파인튜닝 | 도메인 데이터로 가중치 조정 | 용어·형식 정확도 향상 | 지식 갱신 어려움, 재학습 비용 |
| 거절 학습 | 모를 때 답하지 않도록 정렬 | 날조 감소 | 과도한 거절로 유용성 저하 |
| 자기 일관성 | 여러 번 생성해 다수결·불일치 탐지 | 불확실 답변 식별 | 추론 비용 증가 |
| 인용 검증기 | 출처 실존·내용 일치 자동 대조 | 인용 날조·오귀속 탐지 | 검증 모델 자체의 오류 |
| 사람 검토(HITL) | 전문가 최종 승인 | 잔여 위험 통제 | 비용·처리량 한계 |

### 평가 지표
- **충실도**(Faithfulness): 답변의 각 주장이 제공된 근거로 뒷받침되는 비율
- **인용 정밀도/재현율**: 단 인용 중 실제로 주장을 뒷받침하는 비율 / 필요한 주장 중 인용이 달린 비율
- **답변 관련성**: 질문 의도에 맞는 답변인지
- **거절 적정성**: 근거가 없을 때 올바르게 "확인 불가"로 답했는지
- 정답(오라클)을 만들기 어려운 생성 결과는, **입력을 바꿨을 때 출력이 지켜야 할 관계**로 검증하는 메타모픽 테스트를 함께 쓸 수 있다(예: 질의 표현만 바꿨을 때 인용 판례가 바뀌면 불안정 신호).

### 관련 제도·기준
- **인공지능기본법**(2026년 1월 시행): 생성형 AI 결과물 고지 의무, 고영향 AI 사업자 책무
- **NIST AI 600-1**(생성형 AI 프로파일): Confabulation을 생성형 AI 고유 위험으로 명시
- **ISO/IEC 42001**: AI 경영시스템 — 환각 위험을 위험평가·통제 대상에 포함하는 근거

## 3. 기술사 출제 포인트

- 환각의 정의와 구조적 발생 원인(확률적 생성)
- 내재적·외재적 환각, 사실성·충실성 오류 구분
- 인용 날조와 인용 오귀속의 차이
- RAG 기반 근거 생성과 검색 실패 시 위험
- 하이브리드 검색·재순위화로 근거 품질 확보
- 인용 실존·일치 검증과 LLM-as-a-Judge
- 거절 학습과 유용성 간 트레이드오프
- 충실도·인용 정밀도/재현율 등 평가 지표
- 고위험 도메인(법률·의료)의 HITL 책임 구조
- 메타모픽 테스트를 활용한 생성 결과 검증

## 4. 연결 기출 토픽과 예상 변형

- **LLM 성능 향상 기법**: 139회 2교시에 **LLM 파인튜닝/RAG 개념과 RLHF·RAFT 비교**가 출제됐다. 같은 기법을 "환각 완화"라는 목적 기준으로 다시 비교하게 하는 변형이 가능하다.
- **검색과 하네스**: 140회에는 **하네스 엔지니어링 vs 프롬프트 엔지니어링**, **하이브리드 검색**이 신규 키워드로 출제됐다. 둘 다 환각을 구조적으로 줄이는 수단이라, 환각 문항의 적용방안 단락에 그대로 쓸 수 있다.
- **테스트 기법**: 140회 3교시 **메타모픽 테스트**는 정답이 정해지지 않은 AI 출력 검증에 쓰는 기법으로, "생성형 AI 품질 검증" 문항과 결합하기 좋다.
- **데이터 품질**: 139회 3교시·140회 2교시 **AI 학습용 데이터 품질관리**도 환각의 원인(학습 데이터 오류·편향) 측면에서 연결된다.
- **예상 변형**
  - 1교시: "LLM 환각(Hallucination)의 유형과 완화 방안을 설명하시오"
  - 논술: "법률·의료 등 고위험 분야 생성형 AI 서비스의 신뢰성 확보 방안을 RAG·검증·거버넌스 관점에서 논하시오"
  - 평가 융합: "RAG 시스템의 품질 평가 지표를 검색 단계와 생성 단계로 구분해 설명하시오"

## 5. 답안 구성 예시

**단답형**(1교시, 1페이지)
- 정의: 근거·사실과 맞지 않는 내용을 확신 있게 생성하는 LLM의 구조적 결함(NIST: Confabulation)
- 특징 3개: ① 확률적 생성에 기인 ② 내재적/외재적 유형 ③ 출처 날조·오귀속 형태로 고위험 분야에서 치명적
- 구성도 키워드: 입력 통제 → RAG 검색 → 근거 기반 생성 → 인용 검증 → HITL

**논술형(2~4교시) 목차**
1. 개요: 법률 분야 허위 인용 사례와 고위험 도메인 환각의 파급력
2. 구성/비교: 환각 유형표, 5단계 완화 구성도, 완화 기법 비교표
3. 적용방안: 신뢰 원천 한정 RAG, 인용 ID 제약 생성, 자동 인용 검증기, 전문가 승인 워크플로
4. 고려사항: 검색 실패 시 오답 확신, 거절-유용성 균형, 검증 모델 오류, 책임 소재
5. 기술사 제언: 환각률을 단일 수치로 홍보하기보다 **충실도·인용 정밀도·거절 적정성**을 분리해 상시 측정하고, 고위험 분야는 사람 최종 승인을 제도적으로 유지할 것
