## 1. 출제 트렌드 분석 (135~139회)

| 회차 | 유형 | 출제 형태 | 관점 |
|------|------|-----------|------|
| 138회 | 관리 단답 | 데이터 관측가능성(Data Observability) | 데이터 운영 |
| 139회 | 관리 논술 | AI 학습용 데이터 품질관리 | 데이터 품질 |
| 139회 | 관리 논술 | LLM 기반 AX 시스템 구축 | AI 도입 |
| 모의/합숙 | KPC | MLOps·AIOps·DataOps | **140 집중** |

**핵심 인사이트**: 데이터 품질·관측가능성(138·139)에서 **운영 자동화(Ops 3형제)**로 확장. AI 시스템의 지속 운영·거버넌스가 논술화될 가능성.

## 2. 개념·정의

### MLOps
> 머신러닝 모델의 **개발-학습-배포-운영-재학습**을 자동화·표준화하는 방법론. DevOps를 ML로 확장.

### DataOps / AIOps
- **DataOps**: 데이터 파이프라인의 수집-처리-품질-제공을 자동화·거버넌스
- **AIOps**: AI로 **IT 운영**(로그·이상탐지·자동대응)을 지능화
- **LLMOps**: LLM 특화 운영(프롬프트·RAG·평가·비용·가드레일 관리)

## 3. MLOps 파이프라인 아키텍처

```
┌── DataOps ──┐   ┌──────── MLOps ────────┐   ┌── 운영/AIOps ──┐
 데이터 수집  →  피처스토어 → 학습 → 검증 → 레지스트리 → 배포(서빙)
   │             │           │       │         │            │
 품질·계보     재사용      실험추적  평가셋   버전관리     모니터링
 (Lineage)    (Feature)   (Tracking)         (Registry)   (드리프트)
                                                              │
                                              ┌───────────────▼──────────┐
                                              │ 드리프트 감지 → 재학습    │
                                              │ (CT: Continuous Training) │
                                              └───────────────────────────┘
```

## 4. 핵심 기술요소

| 요소 | 역할 |
|------|------|
| CI/CD/CT | 코드·데이터·모델 지속 통합·배포·학습 |
| 피처 스토어 | 피처 재사용·일관성(학습/서빙) |
| 실험 추적 | 파라미터·메트릭·재현성 |
| 모델 레지스트리 | 버전·승격·롤백 |
| 모니터링 | 성능·데이터/개념 드리프트 감지 |
| 거버넌스 | 계보·감사·승인·편향 점검 |

## 5. 드리프트와 지속 운영

- **데이터 드리프트**: 입력 분포 변화 / **개념 드리프트**: 입력-출력 관계 변화
- **대응**: 상시 모니터링 → 임계 초과 시 **재학습(CT)** → 안전 배포(카나리·A/B)
- **LLMOps 특수성**: 프롬프트 버전, RAG 지식 최신화, 환각·품질 평가, 토큰 비용·가드레일

- **핵심**: CI/CD/CT·피처스토어·레지스트리·드리프트 모니터링
