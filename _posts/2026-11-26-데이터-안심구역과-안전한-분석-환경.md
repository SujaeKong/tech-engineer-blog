## 1. 뉴스 요약

뉴시스(11-24)는 **광주에서 미개방 데이터를 분석해 AI 기술개발에 활용할 수 있는 'AI데이터안심존'이 가동**됐다고 보도했다. 공공기관과 기업이 가진 데이터 중에는 개인정보나 기밀 때문에 **밖으로 내보낼 수는 없지만, 분석하면 가치가 큰 데이터**가 많다. 안심구역은 데이터를 밖으로 내보내는 대신 **분석가가 데이터가 있는 통제된 공간으로 들어와 분석하고, 결과만 심사를 거쳐 가져가게** 하는 방식이다. 광주 시설의 구체 운영 방식은 제목 이상으로 확인되지 않으므로, 아래에서는 **데이터 안심구역의 구조와 통제 원리**를 정리한다.

## 2. 핵심 개념

### 정의
**데이터 안심구역**은 개인정보·기밀이 포함돼 외부 개방이 어려운 데이터를 **물리적·기술적으로 통제된 분석 공간 안에서만 이용**하게 하고, **분석 결과물은 심사를 거쳐 안전한 것만 반출**하도록 하는 데이터 활용 환경이다. "데이터를 사람에게 보내는" 개방 방식과 반대로 "**사람이 데이터에 오는**" 방식이라는 점이 핵심이며, 데이터 활용과 보호를 동시에 달성하려는 장치다.

### Five Safes 프레임워크
안전한 데이터 이용 환경을 설계하는 국제적으로 널리 쓰이는 틀로, 다섯 가지 안전을 함께 갖춰야 한다고 본다.

| 요소 | 질문 | 통제 수단 |
|---|---|---|
| 안전한 프로젝트 | 이 분석 목적이 적절하고 공익·정당한가 | 이용 신청 심사, 목적 제한 |
| 안전한 사람 | 이용자를 신뢰할 수 있는가 | 자격 확인, 보안 교육, 서약 |
| 안전한 환경 | 분석 공간이 유출을 막는가 | 폐쇄망, 반입·반출 통제, 감시 |
| 안전한 데이터 | 데이터 자체의 식별 위험이 낮은가 | 가명처리, 필요한 항목만 제공 |
| 안전한 결과물 | 반출 결과로 개인을 알아볼 수 없는가 | 반출 심사, 통계적 노출 제한 |

다섯 요소는 **서로 보완**한다. 환경 통제가 강하면 데이터 가공 수준을 낮춰 분석 가치를 높일 수 있고, 반대로 개방형 환경이라면 데이터 자체를 더 강하게 비식별화해야 한다.

### 데이터 활용 방식 비교

| 구분 | 데이터 개방 | 원격 접근 | 데이터 안심구역 | 가명정보 결합전문기관 |
|---|---|---|---|---|
| 데이터 이동 | 이용자에게 제공 | 이동 없음(원격 분석) | 이동 없음(현장 분석) | 결합 후 제공 또는 내부 분석 |
| 데이터 민감도 | 낮음(공개 가능) | 중간 | 높음 | 높음(서로 다른 기관 데이터) |
| 비식별 수준 | 익명 수준 | 가명·요약 | 가명 수준에서도 가능 | 가명처리 후 결합 |
| 통제 강도 | 낮음 | 중간(접속 통제) | 높음(물리적 통제) | 높음 |
| 이용 편의 | 매우 높음 | 높음 | 낮음(방문 필요) | 중간 |
| 결과 반출 | 제한 없음 | 반출 심사 | 반출 심사 | 반출 심사 |
| 적합 데이터 | 공공데이터 | 통계 마이크로데이터 | 의료·금융·미개방 공공데이터 | 기관 간 결합 데이터 |

### 구성도 ① — 안심구역 분석 환경 아키텍처

```
 [이용 신청]  목적·데이터 항목·분석 계획 → 심의 승인
      │
      ▼
 ┌──────────────── 안심구역(물리적 통제 공간) ────────────────┐
 │  출입 통제 · 개인 기기 반입 금지 · 영상 감시               │
 │                                                            │
 │  [분석 단말(VDI)]  인터넷 차단 · 저장장치·출력 차단          │
 │        │                                                   │
 │        ▼                                                   │
 │  [분석 서버]  분석 도구 · GPU(AI 학습) · 프로젝트별 격리 공간 │
 │        │                                                   │
 │        ▼                                                   │
 │  [데이터 저장소]  가명처리 데이터 · 승인 항목만 · 접근 로그   │
 │                                                            │
 │  [반입 창구]  외부 코드·보조 데이터 반입 심사                │
 └────────────────────────────┬───────────────────────────────┘
                              │ 결과물 반출 신청
                              ▼
 [반출 심사]  재식별 위험 검토 · 통계적 노출 제한 → 승인된 결과만 반출
```

### 반출 심사 — 결과물로 새는 위험 막기
데이터를 밖으로 내보내지 않아도 **분석 결과가 개인 정보를 드러낼 수 있다**. 예컨대 "○○동 30대 여성 희귀질환자 수: 1명" 같은 집계표는 사실상 개인을 특정한다.
- **최소 셀 빈도**: 일정 건수 미만의 칸은 숨기거나 합친다.
- **차분 공격 방지**: 조건을 조금씩 바꾼 두 결과의 차이로 개인을 알아내지 못하게 한다.
- **극단값 처리**: 최댓값·최솟값이 특정인을 드러내지 않게 한다.
- **AI 모델 반출**: 학습된 모델이 학습 데이터를 기억했다가 노출할 수 있다. 모델을 반출할 때는 **기억 위험 점검**과 출력 시험이 필요하다.

### 구성도 ② — 데이터 안심구역 운영 거버넌스

```
 [데이터 제공 기관]  제공 데이터 선정 · 가명처리 · 이용 조건 설정
        │
        ▼
 [운영 기관]  이용 심의 · 환경 운영 · 반출 심사 · 이용 로그 관리
        │
        ▼
 [이용자]  승인된 목적 범위에서 분석 · 결과 반출 신청
        │
        ▼
 [사후 관리]  이용 실적 · 위반 점검 · 성과 공유 → 제공 데이터 확대
```

### 합성데이터와의 연계
안심구역 방문 부담을 줄이는 보완책으로 **합성데이터**가 쓰인다. 원본 데이터의 통계적 특성을 닮은 가상 데이터를 만들어 외부에 제공하면, 이용자는 합성데이터로 분석 코드를 미리 만들고 **최종 분석만 안심구역에서 원본으로** 수행할 수 있다. 다만 합성데이터도 원본과 너무 비슷하면 재식별 위험이 있으므로 유용성과 안전성을 함께 평가해야 한다.

### 관련 법·제도
- **데이터 산업진흥 및 이용촉진에 관한 기본법**: 데이터 안심구역 지정·운영 근거
- **개인정보 보호법**: 가명정보 처리 특례, 가명정보 결합전문기관
- **통계법**: 통계 마이크로데이터 제공과 비밀 보호
- **ISO/IEC 20889**: 개인정보 비식별화 기법 용어·분류
- **Five Safes**: 안전한 데이터 접근 설계 프레임워크(영국 통계청에서 발전)

## 3. 기술사 출제 포인트

- 데이터 안심구역의 정의("사람이 데이터에 오는" 방식)
- Five Safes(프로젝트·사람·환경·데이터·결과물)와 상호 보완 관계
- 데이터 개방·원격 접근·안심구역·결합전문기관 비교
- 안심구역 분석 환경 아키텍처(VDI·폐쇄망·격리 공간·반입·반출 통제)
- 반출 심사(최소 셀 빈도·차분 공격 방지·극단값)
- AI 모델 반출 시 기억 위험 점검
- 합성데이터를 이용한 사전 분석과 원본 최종 분석
- 운영 거버넌스(제공 기관·운영 기관·이용자·사후 관리)
- 데이터산업법·개인정보 보호법·통계법

## 4. 연결 기출 토픽과 예상 변형

- **가명처리**: 139회 1교시에 **가명처리**가 출제됐다. 안심구역은 가명정보를 더 안전한 환경에서 활용하게 해 주는 장치로, 가명처리 문항의 활용 단락에 바로 쓸 수 있다.
- **합성데이터**: 140회 3교시에 **합성데이터 생성과 품질 평가**가 출제됐다. 합성데이터–안심구역 연계 구조는 그 문항의 활용 방안이 된다.
- **데이터 가치평가**: 139회 2교시에 **데이터 가치평가·자산화**가 출제됐다. 미개방 데이터의 가치를 실현하는 유통·활용 방식으로 연결된다.
- **AI 학습 데이터 품질**: 140회 2교시 **AI 학습용 데이터 품질관리**가 출제됐다. 안심구역 안에서의 AI 학습은 민감 데이터 기반 학습의 현실적 경로다.
- **예상 변형**
  - 1교시: "Five Safes 프레임워크를 설명하시오"
  - 1교시: "데이터 안심구역을 설명하시오"
  - 논술: "민감 데이터의 안전한 AI 활용을 위한 데이터 접근 환경 설계 방안을 제시하시오"

## 5. 답안 구성 예시

**단답형**(1교시, 1페이지)
- 정의: 개방이 어려운 민감 데이터를 통제된 공간 안에서만 분석하게 하고, 심사를 거친 결과만 반출하는 데이터 활용 환경
- 특징 3개: ① 데이터 이동 없이 사람이 데이터로 오는 방식 ② Five Safes 기반 다층 통제 ③ 반출 심사로 결과물 재식별 위험 차단
- 구성도 키워드: 이용 신청·심의 → 안심구역(출입 통제·VDI·격리 분석 서버·가명 데이터) → 반출 심사 → 결과 반출

**논술형(2~4교시) 목차**
1. 개요: 미개방 데이터의 활용 수요와 보호 요구
2. 구성/비교: Five Safes 표, 활용 방식 비교표, 분석 환경 아키텍처, 운영 거버넌스도
3. 적용방안: 데이터 제공 기관 확대, AI 학습용 GPU 환경, 합성데이터 사전 분석, 반출 심사 자동화 보조, 원격 안심구역 확대
4. 고려사항: 방문 부담과 이용 편의, 반출 심사 인력, AI 모델 반출 위험, 기관 간 기준 차이
5. 기술사 제언: 안심구역의 성과를 시설 수가 아니라 **활용된 미개방 데이터 수와 반출 결과물의 안전성**으로 평가하고, 합성데이터·원격 접근과 묶어 단계적 접근 체계로 설계할 것
