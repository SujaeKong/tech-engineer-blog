## 1. 뉴스 요약

스마트투데이(11-05)는 **KT와 삼성전자가 AI 기술로 고속철도 구간의 통신 끊김을 29% 줄인 실증 결과**를 보도했다. 시속 300km로 달리는 열차 안에서는 단말이 몇 초마다 기지국을 바꿔야 하고, 이때 연결이 끊기거나 품질이 떨어지는 문제가 반복된다. 앞서 데일리안(11-02)도 **두 회사가 AI로 무선망 자율운용을 검증**했다고 전한 바 있다. 실증에 쓰인 구체 기법은 제목 이상으로 확인되지 않으므로, 아래에서는 **고속 이동 환경의 핸드오버 문제와 최적화 기법**을 답안 재료로 정리한다.

## 2. 핵심 개념

### 정의
**핸드오버**(Handover)는 이동하는 단말이 통화·데이터 연결을 유지한 채 **서비스 기지국(셀)을 다른 기지국으로 넘기는 이동성 관리 절차**다. 고속철도처럼 이동 속도가 빠른 환경에서는 셀에 머무는 시간이 짧아 **핸드오버가 잦고 준비 시간이 부족**해지며, 도플러 편이로 신호 품질도 흔들려 **핸드오버 실패와 연결 끊김**이 늘어난다.

### 구성도 — 기본 핸드오버 절차와 고속 이동 시 실패 지점

```
 단말            서비스 기지국(Source)          대상 기지국(Target)
  │ ① 측정 보고(이웃 셀 신호 세기)  │                         │
  │ ───────────────────────────▶ │                         │
  │                              │ ② 핸드오버 결정          │
  │                              │ ③ 핸드오버 요청 ───────▶ │
  │                              │ ◀─────── ④ 자원 준비·승인 │
  │ ◀── ⑤ 핸드오버 명령 ──────── │                         │
  │ ⑥ 대상 셀 접속(랜덤 액세스) ───────────────────────────▶ │
  │ ◀──────────────────────────────────── ⑦ 접속 완료·경로 전환│

 고속 이동 시 실패 지점
  - ①~⑤가 끝나기 전에 서비스 셀 신호가 급락 → 명령 수신 실패(너무 늦은 핸드오버)
  - 기준이 너무 민감 → 두 셀을 오가는 핑퐁(너무 이른 핸드오버)
  - 터널·절개지 구간의 급격한 신호 변화 → 무선 링크 실패(RLF)
```

### 하드 핸드오버 vs 소프트 핸드오버

| 구분 | 하드 핸드오버 | 소프트 핸드오버 |
|---|---|---|
| 방식 | 기존 연결을 끊고 새 연결(Break-before-Make) | 새 연결을 먼저 맺고 기존 연결 해제(Make-before-Break) |
| 동시 연결 | 1개 | 2개 이상 |
| 대표 기술 | GSM, LTE, 5G NR(기본) | CDMA, WCDMA |
| 순간 단절 | 있음(짧음) | 거의 없음 |
| 자원 사용 | 효율적 | 여러 셀 자원 동시 점유 |
| 전제 조건 | — | 인접 셀이 같은 주파수 사용 |

LTE·5G는 기본적으로 하드 핸드오버라 순간 단절을 줄이는 보완 기법이 필요하다. 아래의 DAPS가 그 예다.

### 3GPP의 핸드오버 개선 기법

| 기법 | 원리 | 고속 이동에서의 효과 |
|---|---|---|
| 조건부 핸드오버(CHO, Rel-16) | 핸드오버 명령을 미리 받아 두고, 조건이 충족되면 단말이 스스로 실행 | 서비스 셀 신호가 급락해도 명령은 이미 수신 → 실패 감소 |
| DAPS 핸드오버(Rel-16) | 이동 중 기존·대상 셀에 동시 연결 유지 | 사실상 무단절(0ms에 가까운 중단) |
| 고속열차(HST) 시나리오 요구사항 | 고속 이동에 맞춘 성능 요구·주파수 오차 보정 | 도플러 편이 대응 |
| 셀 결합(동일 셀 확장) | 선로를 따라 여러 송신점을 하나의 셀로 운용 | 핸드오버 횟수 자체를 줄임 |
| 경로 예측 기반 사전 준비 | 정해진 선로·속도로 다음 셀을 예측 | 준비 시간 확보 |

고속철도는 **이동 경로가 고정돼 있다**는 점이 일반 이동 환경과 다르다. 열차 위치와 속도를 알면 다음 셀을 거의 정확히 예측할 수 있어, AI 기반 예측·파라미터 최적화의 효과가 크다.

### 핸드오버 파라미터
- **A3 이벤트**: 이웃 셀 신호가 서비스 셀보다 일정 값 이상 강해지면 측정 보고
- **히스테리시스**(Hysteresis): 경계에서 핑퐁을 막기 위한 여유값
- **TTT**(Time-to-Trigger): 조건이 일정 시간 유지돼야 보고 — 고속 이동에서는 길면 늦은 핸드오버, 짧으면 핑퐁
- **CIO**(셀별 오프셋): 특정 셀 쌍의 핸드오버를 앞당기거나 늦추는 조정값

고정값으로는 구간·속도·시간대별 최적값을 맞추기 어렵다. **구간별 실패 이력을 학습해 파라미터를 자동 조정**하는 것이 AI 적용의 대표 사례다.

### 관련 표준
- **3GPP Rel-16**: 조건부 핸드오버(CHO), DAPS 핸드오버
- **3GPP 고속열차(HST) 요구사항**: 고속 이동 환경의 성능 요구
- **LTE-R**: 철도 전용 LTE 기반 무선통신망(열차 제어·운영용) — 승객용 이동통신과 구분

## 3. 기술사 출제 포인트

- 핸드오버의 정의와 절차(측정 보고→결정→준비→명령→접속)
- 고속 이동 환경의 핸드오버 문제(잦은 핸드오버·도플러·RLF)
- 너무 늦은 핸드오버·너무 이른 핸드오버·핑퐁
- 하드 핸드오버와 소프트 핸드오버 비교
- 조건부 핸드오버(CHO)의 원리와 효과
- DAPS 핸드오버와 무단절 이동성
- 핸드오버 파라미터(A3·히스테리시스·TTT·CIO)
- 고정 경로 특성을 활용한 AI 예측·파라미터 최적화
- 승객용 이동통신과 철도 전용망(LTE-R) 구분

## 4. 연결 기출 토픽과 예상 변형

- **다중접속**: 140회 3교시 **CSMA/CA·CDMA·TDMA**가 출제됐다. CDMA의 소프트 핸드오버는 다중접속 방식과 이동성 관리를 잇는 대표 논점이다.
- **5G**: 블로그 통합 기출 분석(`exam_trend_integrated.json`) 기준 **5G는 기출 13회**로 네트워크 최빈출 키워드다. 5G의 이동성 개선(CHO·DAPS)은 5G 문항의 하위 주제로 쓸 수 있다.
- **자율운용**: 11월 3일 정리한 O-RAN RIC의 xApp이 바로 핸드오버 파라미터를 실시간 조정하는 실행 계층이다. 두 주제를 묶어 "AI 기반 이동성 최적화" 문항으로 연결할 수 있다.
- **예상 변형**
  - 1교시: "하드 핸드오버와 소프트 핸드오버를 비교하시오"
  - 1교시: "5G 조건부 핸드오버(CHO)를 설명하시오"
  - 논술: "고속 이동 환경(고속철도·차량)의 이동통신 품질 확보를 위한 핸드오버 최적화 방안을 제시하시오"

## 5. 답안 구성 예시

**단답형**(1교시, 1페이지)
- 정의: 이동 단말이 연결을 유지한 채 서비스 셀을 바꾸는 이동성 관리 절차
- 특징 3개: ① 고속 이동 시 잦은 핸드오버·준비 시간 부족 ② CHO·DAPS로 실패·단절 감소 ③ A3·TTT·CIO 파라미터 최적화
- 구성도 키워드: 측정 보고 → 핸드오버 결정 → 대상 셀 준비 → 명령 → 접속·경로 전환

**논술형(2~4교시) 목차**
1. 개요: 고속철도 구간 통신 끊김 문제와 AI 실증
2. 구성/비교: 핸드오버 절차·실패 지점 구성도, 하드 vs 소프트 비교표, 3GPP 개선 기법표
3. 적용방안: 선로 기반 셀 예측, CHO 적용, 구간별 파라미터 자동 최적화, 셀 결합으로 핸드오버 횟수 감소
4. 고려사항: 터널·절개지 신호 급변, 열차 차체 투과 손실, 기지국 간 동기, 최적화 결과 검증
5. 기술사 제언: 고속철도처럼 **경로가 고정된 구간부터 AI 이동성 최적화를 적용**하고, 핸드오버 실패율·RLF·끊김 시간을 구간별로 상시 측정해 파라미터 변경 효과를 검증할 것
