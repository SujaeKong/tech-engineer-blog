## 1. 뉴스 요약

2026-06-11 우리은행이 생성형 AI 기반 **'인공지능(AI) 포용채무진단' 서비스를 출시**했다고 비즈니스포스트·스마트경제·더글로벌기빙뉴스 등 다수 매체가 보도했다. 마이데이터로 수집한 고객의 **여러 금융기관 대출·연체 정보를 통합**하고, 여기에 LLM을 결합해 부채 상태를 한눈에 진단하고 상환 우선순위·채무조정 제도 안내까지 제공하는 'AI 의사' 콘셉트의 서비스다.

이 서비스의 본질은 **마이데이터 표준 API로 흩어진 개인신용정보를 모으고, 정제·통합된 데이터 위에 LLM 분석을 얹는 데이터 아키텍처**다. 마이데이터(본인신용정보관리업)는 데이터 이동권·표준 API·데이터 결합이라는 데이터베이스 영역의 핵심 주제를 모두 포함하는 빈출 토픽으로, 생성형 AI와의 결합 사례라는 시의성까지 갖춰 출제 가치가 높다.

## 2. 핵심 개념

### 마이데이터(본인신용정보관리업)의 개념

마이데이터는 **정보주체가 자신의 개인(신용)정보에 대한 이동권(전송요구권)을 행사**해, 여러 기관에 흩어진 본인 데이터를 한 사업자에게 모아 통합 조회·활용하게 하는 제도다. 신용정보법 개정(데이터 3법)으로 법제화됐으며, 핵심 구성요소는 다음과 같다.

- **전송요구권**: 정보주체가 정보제공자에게 본인 데이터를 제3자(마이데이터 사업자)에게 전송하도록 요구할 권리
- **표준 API**: 기관 간 데이터 전송을 위한 표준화된 인터페이스 규격(인증, 자원 API, 전송 주기)
- **통합인증**: 공동·금융인증서 등을 통한 본인확인과 전송요구 의사 확인
- **중계기관**: 중소형 정보제공자의 API 부담을 대신하는 게이트웨이 역할

### 스크래핑 방식과 표준 API 방식의 비교

| 구분 | 스크래핑(기존) | 마이데이터 표준 API |
|------|---------------|---------------------|
| 수집 방식 | 고객 인증정보를 위임받아 화면 긁기 | 표준 규격 API 직접 호출 |
| 인증 정보 | ID/비밀번호·인증서를 사업자가 보관 | 토큰 기반, 인증정보 미보관 |
| 데이터 품질 | 화면 변경 시 오류, 비정형 | 표준 스키마, 정형화된 항목 |
| 보안·통제 | 과다 수집 위험, 추적 곤란 | 전송요구 범위 내 수집, 이력 관리 |
| 실시간성 | 불안정 | 정기·요구 시 전송으로 안정적 |

### 마이데이터-LLM 결합 데이터 아키텍처

이번 서비스 유형의 일반적 처리 흐름은 **수집 → 통합·정제 → 분석 → 생성형 안내**의 데이터 파이프라인으로 구성된다.

- **수집 계층**: 표준 API로 다기관 대출·카드·연체 데이터 수집, 전송요구 범위·주기 관리
- **통합·정제 계층**: 기관별 코드·상품명 표준화, 중복 제거, 고객 단위 통합 뷰(Single View) 구성 — 데이터 품질 관리(정합성·완전성)가 분석 신뢰도를 좌우
- **분석 계층**: 부채 구조 분석, 상환 여력 산출 등 정형 분석(룰·모델 기반)
- **생성 계층**: LLM이 분석 결과를 근거로 진단 리포트·제도 안내를 자연어로 생성 — 수치 계산은 정형 엔진이 담당하고 LLM은 설명·안내에 한정해 할루시네이션 위험을 통제(그라운딩)

### 데이터 거버넌스 고려사항

개인신용정보는 민감도가 높아 **목적 제한(수집 목적 내 이용), 보유기간·삭제 관리, 전송·접근 이력 감사, 가명처리 후 모델 개선 활용** 등 거버넌스 통제가 필수다. 특히 LLM에 개인신용정보를 입력하는 구간은 **망분리·내부 호스팅 또는 비식별 처리** 같은 보호조치와 개인정보 영향평가가 요구된다.
