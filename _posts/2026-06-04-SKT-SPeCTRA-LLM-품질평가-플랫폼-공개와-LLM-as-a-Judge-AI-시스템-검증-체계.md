## 1. 뉴스 요약

2026-06-01 SK텔레콤 뉴스룸은 **"AI가 AI를 평가하다, SKT의 LLM 품질 평가 플랫폼 'SPeCTRA(SK Platform for Comprehensive Testing & Robust Assessment)'"**를 공개했다. 핵심은 ① **다수의 LLM 후보 모델을 동일 데이터셋·동일 기준으로 자동 채점·비교**해 운영에 투입할 모델을 선택하는 **체계화된 평가 파이프라인**을 사내 표준 플랫폼으로 정립, ② 단답·요약·코드·도구사용 등 **다차원 태스크별 평가셋과 LLM-as-a-Judge 기반 자동 채점**을 결합, ③ 기준 모델(Baseline) 대비 **품질·환각률·지연·비용 트레이드오프**를 가시화해 의사결정 근거를 제공한다는 점이다. 동일 시기 과기정통부의 **AI SW 품질관리 역량강화 사업**(이전 기보도)과 **AI SW 대가체계 개편 착수** 흐름이 맞물리면서 **AI 시스템 품질·시험 표준화**가 산업·정책 양면에서 가속화되고 있다. 기술사 소프트웨어공학 영역에서 **AI/LLM 품질·시험·검증**은 신규 출제 핵심 토픽이며, ISO/IEC 25010·25059(AI 품질모델)·AI RMF·ISO/IEC 42001과 직결된다.

## 2. 핵심 개념

### 전통 SW 품질평가 vs LLM 품질평가 비교

| 항목 | 전통 SW 테스트 | LLM 품질평가 |
|---|---|---|
| 결과 결정성 | 결정적(같은 입력→같은 출력) | 확률적·비결정적 |
| 정답 정의 | 명시적 기대값 | 다정답·주관·맥락 의존 |
| 합·불 판정 | 단정 비교(assert) | 점수·랭킹·유사도 |
| 평가 주체 | 사람·자동 어설션 | 사람·룰·다른 LLM(Judge) |
| 핵심 지표 | 결함밀도·커버리지 | 정확도·환각률·유해성·지연·비용 |
| 회귀 관리 | 단위·통합 테스트 회귀 | 모델 버전·프롬프트·RAG 코퍼스 회귀 |

### LLM 평가 4축과 대표 지표

| 평가 축 | 대상 | 대표 지표/기법 |
|---|---|---|
| 능력(Capability) | 추론·지식·수학·코드 | MMLU, GSM8K, HumanEval, KMMLU |
| 충실성(Faithfulness) | 환각·근거 일치 | RAGAS, Faithfulness, Groundedness |
| 안전성(Safety) | 유해·편향·프라이버시 | TruthfulQA, ToxiGen, BBQ, 레드팀 |
| 운영성(Operations) | 지연·처리량·비용 | p95 Latency, TPS, $/1k token |

### SPeCTRA류 LLM 평가 플랫폼 아키텍처

| 계층 | 구성요소 | 역할 |
|---|---|---|
| 평가셋 | 다태스크 골든셋, 도메인 셋, 합성 셋 | 평가 입력·기대값 관리 |
| 실행 엔진 | 모델 라우터, 배치 추론, 도구 시뮬레이터 | 다수 모델 동시 채점 |
| 채점기 | 규칙 채점, 임베딩 유사도, LLM-as-a-Judge, 사람 검토 | 다중 채점·앙상블 |
| 메트릭/대시보드 | 품질·환각·안전·지연·비용 | 모델 간 트레이드오프 비교 |
| 회귀·실험관리 | 모델·프롬프트·RAG 버전 트래킹 | 변경 영향 추적 |
| 거버넌스 | 평가 이력, 모델 카드, 승인 | 운영 투입 의사결정 |

### LLM-as-a-Judge 패턴

| 패턴 | 설명 | 주의점 |
|---|---|---|
| Pointwise | 답변 1개에 점수 부여 | 채점 일관성 보정 필요 |
| Pairwise | 두 답변 비교 선호 | 위치·자기선호 편향 통제 |
| Rubric | 기준 항목별 채점 | 루브릭 설계 품질 좌우 |
| 다중 Judge 앙상블 | 여러 모델로 채점 평균 | 비용·지연 증가 |

## 3. 기술사 출제 포인트

### 개념 정의와 필요성

- **LLM 품질평가 플랫폼**: 다수의 LLM·프롬프트·RAG 구성에 대해 동일 평가셋·동일 기준으로 자동 채점·비교·회귀를 수행하는 표준화된 시험 체계
- **LLM-as-a-Judge**: 자연어 응답의 다정답·주관 평가를 다른 LLM이 루브릭에 따라 채점하는 기법
- **EvalOps**: 데이터·평가셋·모델·프롬프트·결과·지표를 형상관리하며 지속적으로 평가·개선하는 운영 체계(MLOps의 평가 확장)
- **필요성**: ① LLM의 비결정성·환각 위험 통제, ② 모델/프롬프트/RAG 변경의 회귀 영향 파악, ③ 다수 후보 모델의 객관 비교, ④ 규제(AI 기본법·AI RMF·ISO 42001)의 시험·기록 요구 충족

### 기존 방식과의 비교

- **단위·통합 테스트**: 결정적 출력 검증에 최적, 자연어 생성 평가에는 부적합
- **사람 평가(휴먼 평가)**: 신뢰도 높지만 비용·시간 큼, 회귀 어려움
- **단일 벤치마크 점수**: 도메인·실사용과 괴리, 과적합·평가 누출 위험
- **EvalOps/LLM-as-a-Judge**: 다태스크·다지표 자동화로 확장성·반복성 확보, 사람 평가는 표본 검증에 활용

### 아키텍처 구성요소

- **평가셋 관리**: 골든셋(도메인 정답), 합성셋(LLM 생성), 적대적 셋(유해·편향), 버전·라이선스·민감정보 분리
- **실행 엔진**: 모델 게이트웨이, 배치 추론, 도구 호출 시뮬레이터, 비용·지연 측정
- **채점기**: 규칙 기반(정규식·EM·F1·BLEU·ROUGE), 임베딩 유사도, LLM-Judge, 사람 라벨러 큐
- **지표·대시보드**: 능력·충실성·안전성·운영성 4축 그래프, 모델 카드, 회귀 알람
- **회귀·실험관리**: 모델·프롬프트·RAG·툴 버전을 단일 실험 단위로 트래킹, 통계적 유의성 검증
- **연동**: CI/CD 파이프라인, A/B 테스트, 모델 레지스트리, 옵저버빌리티, 데이터 거버넌스

### 도입 시 고려사항

- **평가 누출(Test Leakage)**: 공개 벤치마크가 학습데이터에 포함되었는지 점검, 사내 골든셋 별도 관리
- **Judge 편향**: 위치·길이·자기선호 편향 통제, 다중 Judge 앙상블, 사람 표본 보정
- **신뢰구간·통계검정**: 단일 점수 비교 금지, 부트스트랩·MC 분석, 효과크기 산정
- **도메인 적합성**: 일반 벤치마크 + 도메인 골든셋 결합, KMMLU/한국어 특화 셋 활용
- **비용·지연 트레이드오프**: 품질만이 아닌 p95 지연·토큰 단가·캐시·라우팅 종합 평가
- **거버넌스/규제**: ISO/IEC 25059 AI 품질모델, ISO/IEC 42001 AIMS, NIST AI RMF의 측정·관리 기능과 연계
- **인적 검증**: 적대적 셋·민감 사례는 인간 검수 우선, Human-in-the-Loop
- **회귀 관리**: 프롬프트·RAG 코퍼스 변경이 출시 후 품질에 미치는 영향 감시, 모델 드리프트 알람
- **상호운용**: OpenLLM Leaderboard·HELM·BIG-bench 호환 결과 산출, 내부 표준 메트릭 정의
