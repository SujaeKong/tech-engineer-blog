## 1. 뉴스 요약

한국강사신문(11-14)은 **연세대학교가 AI-RAN Alliance 서울 총회를 개최**하고 엔비디아 등 글로벌 기업과 차세대 AI 통신 기술 협력을 모색했다고 보도했다. AI-RAN은 기지국 무선접속망(RAN)을 가속 컴퓨팅 인프라 위에서 소프트웨어로 돌리고, 같은 인프라에서 AI 추론까지 처리하겠다는 구상이다. 이 구상은 기지국 기능을 어디서 나누고 무엇을 범용 서버로 옮기느냐는 **vRAN·기능 분할** 문제를 바탕에 깔고 있다. 총회의 의제와 참여 기업 목록은 제목 이상으로 확인되지 않으므로, 아래에서는 **RAN 구조의 진화와 기능 분할, AI-RAN 인프라 운영**을 답안 재료로 정리한다.

## 2. 핵심 개념

### 정의
**vRAN**(가상화 RAN)은 기지국의 기저대역(Baseband) 처리를 전용 하드웨어 대신 **범용 서버 위의 소프트웨어로 구현**한 무선접속망이다. **기능 분할**(Functional Split)은 기지국 프로토콜 스택을 **CU·DU·RU 중 어디에서 나눌지 정하는 기준**으로, 분할 지점에 따라 프런트홀 대역폭·지연 요구와 집중화 이득이 달라진다. **AI-RAN**은 GPU 등 가속 컴퓨팅 인프라에서 **RAN 처리와 AI 워크로드를 함께 운용**하고, AI로 무선 성능을 높이는 구조다.

### 구성도 ① — 기지국 구조의 진화

```
 D-RAN   [안테나+RU+BBU]가 셀 사이트마다 일체형 설치
   │       → 사이트마다 장비·전력·공조 필요, 자원 공유 불가
   ▼
 C-RAN   RU만 사이트에 두고 BBU를 집중국에 모음(BBU 풀)
   │       → 협력 처리·운영 효율, 대용량 프런트홀(CPRI) 필요
   ▼
 vRAN    BBU 기능을 범용 서버 소프트웨어로 가상화(CU·DU)
   │       → 탄력적 확장, 하드웨어·소프트웨어 분리
   ▼
 O-RAN   CU·DU·RU 사이 인터페이스를 개방·표준화, RIC로 지능화
   │       → 멀티벤더 구성
   ▼
 AI-RAN  가속 컴퓨팅 위에서 RAN + AI 추론 공동 운용
           → AI-for-RAN · AI-and-RAN · AI-on-RAN
```

### 구성도 ② — 프로토콜 스택과 분할 지점

```
  [5G 코어]
      │ 백홀(NG)
  ┌───┴──────────── CU ─────────────┐
  │  RRC · SDAP · PDCP               │
  └───┬──────────────────────────────┘
      │ ◀ Option 2 (미드홀, F1 인터페이스)
  ┌───┴──────────── DU ─────────────┐
  │  RLC · MAC · High-PHY            │  ← 실시간 처리, L1 가속 대상
  └───┬──────────────────────────────┘
      │ ◀ Option 7.2x (프런트홀, O-RAN 개방 규격)
  ┌───┴──────────── RU ─────────────┐
  │  Low-PHY(FFT·빔포밍 일부) · RF   │
  └───┬──────────────────────────────┘
      │ ◀ Option 8 (RF만 분리, 전통 CPRI)
   [안테나]
```

분할 지점이 아래(RU 쪽)로 내려갈수록 집중국에서 할 수 있는 처리가 많아지지만, 프런트홀이 실어야 하는 데이터와 지연 요구가 급격히 커진다.

### 기능 분할 옵션 비교

| 구분 | Option 2(상위 분할) | Option 7.2x(하위 분할) | Option 8(RF 분할) |
|---|---|---|---|
| 분할 위치 | PDCP와 RLC 사이 | High-PHY와 Low-PHY 사이 | PHY와 RF 사이 |
| 구간 명칭 | 미드홀(CU–DU) | 프런트홀(DU–RU) | 프런트홀(BBU–RRH) |
| 전송 대역폭 | 사용자 트래픽 수준으로 낮음 | 중간(주파수 영역 데이터) | 매우 높음(디지털화된 무선 신호) |
| 지연 요구 | 비교적 완화(ms 단위) | 엄격(마이크로초 단위) | 매우 엄격 |
| 집중화 이득 | 제한적 | 협력 스케줄링 등 상당 | 최대 |
| 대표 규격 | 3GPP F1 | O-RAN 프런트홀, eCPRI | CPRI |
| 주 용도 | CU 집중화·클라우드 배치 | 개방형 RAN의 표준 분할 | 전통 C-RAN |

### RAN 구조 비교

| 구분 | D-RAN | C-RAN | vRAN | AI-RAN |
|---|---|---|---|---|
| 기저대역 처리 위치 | 셀 사이트 | 집중국 BBU 풀 | 집중국·엣지 서버 | 엣지 가속 컴퓨팅 노드 |
| 하드웨어 | 전용 장비 | 전용 장비 | 범용 서버(+가속기) | GPU 등 가속 서버 |
| 자원 이용률 | 낮음(피크 기준 설계) | 풀링으로 개선 | 탄력 할당 | RAN 유휴 자원을 AI에 활용 |
| 벤더 종속 | 높음 | 높음 | 완화 | 완화(개방 인터페이스 전제) |
| 운영 방식 | 사이트별 관리 | 집중 관리 | 클라우드 네이티브 | RAN·AI 통합 오케스트레이션 |
| 주요 과제 | 사이트 비용 | 프런트홀 용량 | 실시간 성능 확보 | 실시간 RAN 우선 보장·전력 |

### L1 가속 방식
DU의 High-PHY(채널 코딩·변조 등)는 연산량이 크고 처리 마감 시간이 짧아 범용 CPU만으로는 부담이 크다.
- **룩어사이드**(Lookaside): CPU가 처리하다가 LDPC 디코딩 같은 무거운 함수만 가속기에 넘기고 결과를 돌려받는다. 기존 소프트웨어를 살리기 쉽지만 CPU–가속기 사이 데이터 왕복이 생긴다.
- **인라인**(Inline): High-PHY 전체를 가속기가 처리하고 결과를 바로 다음 단계로 넘긴다. 왕복이 없어 지연·효율에 유리하지만 가속기 플랫폼에 대한 의존이 커진다.

GPU 기반 AI-RAN은 대체로 인라인 방식으로 L1을 처리하면서, 남는 연산 자원을 AI 추론에 배분하는 그림을 그린다.

### AI-RAN 공동 운용의 쟁점
- **우선순위 보장**: RAN 처리는 슬롯 단위 마감 시간을 넘기면 곧바로 통신 품질 저하로 이어진다. AI 작업은 RAN 부하가 낮을 때만 자원을 쓰도록 **선점·격리 정책**이 필요하다.
- **이용률 개선**: 기지국은 출퇴근 시간 등 피크를 기준으로 설계돼 평소 자원이 남는다. 이 유휴 자원을 엣지 AI 추론에 쓰는 것이 AI-RAN의 경제성 논리다.
- **전력**: GPU 서버의 전력 소모가 기존 전용 장비보다 커질 수 있어 **비트당·추론당 전력**으로 효과를 따져야 한다.
- **동기화**: 하위 분할 프런트홀은 정밀한 시각 동기가 필수라 PTP·SyncE 설계가 함께 들어간다.

### 관련 표준
- **3GPP TR 38.801**: 5G 무선접속망 기능 분할 옵션(Option 1~8) 정의
- **3GPP F1 인터페이스**: CU–DU 사이(Option 2) 표준 인터페이스
- **O-RAN Alliance 프런트홀 규격**: 7.2x 분할의 DU–RU 개방 인터페이스
- **eCPRI**: 패킷(이더넷) 기반 프런트홀 전송 규격, CPRI보다 대역폭 효율 개선
- **IEEE 1588 PTP·SyncE, ITU-T G.8275.1**: 프런트홀 시각·주파수 동기

## 4. 연결 기출 토픽과 예상 변형

- **5G**: 블로그 통합 기출 분석(`exam_trend_integrated.json`) 기준 **5G는 기출 13회**로 네트워크 영역의 대표 빈출 키워드다. 5G 기지국 구조와 기능 분할은 5G 문항에서 구성도로 쓰기 좋은 재료다.
- **엣지 컴퓨팅**: 139회 1교시에 **엣지 컴퓨팅과 클라우드 컴퓨팅 비교**가 출제됐고, 통합 분석 기준 엣지 컴퓨팅은 기출 9회 키워드다. AI-on-RAN은 기지국 엣지에서 AI 추론을 제공하는 엣지 컴퓨팅의 한 형태다.
- **AI 인프라 전력효율**: 140회 4교시 **AI 추론 인프라 벤치마크·전력효율**, 140회 1교시 **NPU**가 출제됐다. AI-RAN의 GPU 공유와 전력 평가 단락으로 연결된다.

## 5. 답안 구성 예시

**단답형**(1교시, 1페이지)
- 정의: 기지국 프로토콜 스택을 CU·DU·RU로 나누는 기준으로, 분할 지점에 따라 프런트홀 요구와 집중화 이득이 달라지는 구조
- 특징 3개: ① Option 2(미드홀, 요구 완화) ② Option 7.2x(O-RAN 표준 하위 분할) ③ Option 8(CPRI, 최대 집중화·대용량 프런트홀)
- 구성도 키워드: CU(RRC·PDCP) –F1– DU(RLC·MAC·High-PHY) –7.2x– RU(Low-PHY·RF)

**논술형(2~4교시) 목차**
1. 개요: AI-RAN 협력 확대와 가상화 기지국 전환
2. 구성/비교: 구조 진화도, 분할 지점 구성도, 분할 옵션 비교표, RAN 구조 비교표
3. 적용방안: 7.2x 개방 프런트홀 채택, 인라인 L1 가속, RAN 우선 선점 스케줄링, RIC 기반 AI 최적화, 엣지 AI 추론 서비스
4. 고려사항: 프런트홀 광 인프라와 동기 설계, 실시간 마감 보장, 전력 증가, 멀티벤더 연동 시험
5. 기술사 제언: AI-RAN의 효과를 **통신 품질을 해치지 않는 범위에서 늘어난 유휴 자원 활용도와 추론당 전력**으로 측정하고, 분할 지점은 지역별 광 인프라 여건에 맞춰 혼합 배치할 것
