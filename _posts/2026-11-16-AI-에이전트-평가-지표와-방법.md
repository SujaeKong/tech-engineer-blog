## 1. 뉴스 요약

인공지능신문(11-12)은 **한국인공지능검증원이 오스트리아 AIT와 AI 신뢰성 검증 플랫폼을 개발하고, 평가 대상을 AI 에이전트까지 확대**한다고 보도했다. 전자신문(11-13)은 ETRI가 로봇 AI를 평가하는 기술 '트리니티'를 내놓았다고 전했다. 모델이 질문에 답하는 수준을 넘어 **스스로 계획을 세우고 도구를 호출해 실제 시스템을 바꾸는 에이전트**가 늘면서, "답이 맞는가"만으로는 품질을 판단할 수 없게 된 것이다. 플랫폼의 평가 항목과 방법은 제목 이상으로 확인되지 않으므로, 아래에서는 **AI 에이전트 평가의 지표와 방법론**을 정리한다.

## 2. 핵심 개념

### 정의
**AI 에이전트 평가**는 LLM 기반 에이전트가 목표를 받아 **계획 수립 → 도구 호출 → 환경 관찰 → 재계획**을 반복하며 과업을 수행하는 전 과정을 **결과·경로·안전성·비용** 측면에서 측정하는 활동이다. 단일 응답을 채점하는 LLM 평가와 달리, 여러 단계에 걸친 행동의 연쇄(궤적)와 그 행동이 환경에 남긴 **부작용**까지 평가 대상에 포함된다.

### LLM 평가 vs 에이전트 평가

| 구분 | LLM 평가 | AI 에이전트 평가 |
|---|---|---|
| 평가 단위 | 질문 1건–응답 1건 | 과업 1건–다단계 궤적 |
| 정답 형태 | 기준 답안·채점 기준 | 최종 환경 상태, 허용 경로의 집합 |
| 주요 실패 | 환각·부정확·유해 응답 | 잘못된 도구 선택·무한 반복·권한 밖 행동·부작용 |
| 환경 필요 | 불필요(텍스트만) | 샌드박스(모의 API·DB·웹·파일 시스템) |
| 결과 변동성 | 있음 | 단계마다 누적되어 더 큼 |
| 비용 지표 | 토큰·응답 지연 | 단계 수·도구 호출 수·총 소요 시간·총 비용 |
| 안전 평가 | 유해 출력 차단 | 프롬프트 주입 저항·권한 준수·되돌릴 수 없는 행동 통제 |

### 평가의 세 층위
- **결과 평가**(Outcome): 과업이 끝났을 때 환경이 목표 상태인가. 예) 예약이 정확히 1건 생성됐는가. 규칙 기반 상태 검사로 자동화하기 좋다.
- **궤적 평가**(Trajectory): 거기까지 가는 경로가 적절했는가. 불필요한 단계, 잘못된 도구 호출 뒤의 복구, 정책 위반 여부를 본다. 결과가 맞아도 경로가 위험하면 감점한다.
- **구성요소 평가**(Component): 계획 모듈, 도구 선택, 인자 생성, 검색·메모리 등 부품 단위 성능. 실패 원인을 좁히는 데 쓴다.

### 구성도 — 에이전트 평가 하네스

```
 [과업 세트]  과업 지시 + 초기 환경 상태 + 성공 조건 + 금지 행동
     │
     ▼
 [샌드박스 환경]  모의 API · 테스트 DB · 웹 · 파일 시스템 (실제 시스템과 격리)
     │
     ▼
 [에이전트 실행]  계획 → 도구 호출 → 관찰 → 재계획 … (같은 과업 k회 반복)
     │
     ▼
 [궤적 로그]  모든 단계의 입력·도구 호출·인자·결과·소요 시간·비용
     │
     ▼
 [평가기]
   ├ 규칙 기반: 최종 상태 검사, 금지 행동 탐지
   ├ LLM-as-a-Judge: 경로 적절성·응답 품질 채점
   └ 사람 평가: 판정 표본 검수, 모호한 사례 판정
     │
     ▼
 [지표 집계]  성공률 · 일관성 · 효율 · 안전 · 비용
     │
     ├──▶ [배포 게이트]  기준 미달 시 배포 중단
     └──▶ [운영 모니터링]  실사용 궤적 표본 재평가 → 과업 세트 보강
```

### 주요 평가 지표

| 지표 | 의미 | 측정 방법 |
|---|---|---|
| 과업 성공률 | 목표 상태에 도달한 비율 | 최종 환경 상태 규칙 검사 |
| pass^k(일관성) | 같은 과업을 k번 모두 성공한 비율 | 반복 실행 후 전체 성공 여부 |
| 단계 효율 | 최소 경로 대비 실제 단계 수 | 궤적 길이 비교 |
| 도구 호출 정확도 | 올바른 도구를 올바른 인자로 호출한 비율 | 호출 로그와 기대 호출 비교 |
| 안전 위반률 | 권한 밖 행동·금지 행동 발생 비율 | 금지 행동 규칙, 주입 공격 시나리오 |
| 사람 개입률 | 확인·승인 요청이 필요했던 비율 | 운영 로그 |
| 비용·지연 | 과업당 토큰·호출·시간 | 궤적 로그 집계 |

**pass@k와 pass^k는 다르다.** pass@k는 k번 중 한 번이라도 성공하면 통과로 보는 지표라 "가능성"을 보여주고, pass^k는 k번 모두 성공해야 통과라 "믿고 맡길 수 있는가"를 보여준다. 업무 자동화에 투입할 에이전트라면 pass^k가 더 현실적인 기준이다.

### 대표 벤치마크
- **SWE-bench**: 실제 오픈소스 저장소의 이슈를 해결하는 코드 수정 과업
- **WebArena**: 모의 웹사이트에서 쇼핑·게시판 관리 등 웹 과업 수행
- **τ-bench**: 사용자와 대화하며 도구·정책을 지켜 업무를 처리하는 과업, pass^k 일관성 평가로 알려짐
- **GAIA**: 검색·추론·도구 사용이 섞인 범용 비서 과업
- **OSWorld**: 실제 운영체제 화면을 조작하는 컴퓨터 사용 과업

벤치마크 점수는 비교 기준일 뿐이다. 조직의 실제 업무 과업과 정책을 반영한 **자체 과업 세트**가 배포 판단의 근거가 되어야 한다.

### 평가의 함정
- **데이터 오염**: 공개 벤치마크가 학습 데이터에 섞이면 점수가 부풀려진다. 비공개 과업을 별도로 유지한다.
- **비결정성**: 같은 입력에도 결과가 달라지므로 1회 실행 점수는 신뢰하기 어렵다. 반복 실행과 신뢰구간 제시가 필요하다.
- **판정자 편향**: LLM-as-a-Judge는 긴 답변·특정 문체를 선호하는 경향이 있어 사람 검수 표본으로 판정 일치도를 확인한다.
- **환경 재현성**: 외부 API·웹 상태가 바뀌면 같은 과업도 결과가 달라진다. 고정된 모의 환경을 쓴다.
- **부작용**: 실제 시스템에서 평가하면 메일 발송·결제 같은 되돌릴 수 없는 행동이 생긴다. 반드시 격리된 샌드박스에서 평가한다.

### 관련 표준·기준
- **ISO/IEC 25059**: AI 시스템 품질 모델(SQuaRE 기반)
- **ISO/IEC TR 24029-1**: 신경망 강건성 평가 개요
- **ISO/IEC 42001**: AI 경영시스템 — 성능 모니터링·평가 요구
- **NIST AI RMF**: 측정(Measure) 기능에서 위험 지표 정의·평가
- **인공지능기본법**: 고영향 AI 사업자의 위험관리·설명 방안 등 책무

## 4. 연결 기출 토픽과 예상 변형

- **멀티에이전트**: 139회 3교시에 **MAS**(멀티 에이전트 시스템)가 출제됐다. 에이전트 구조를 물은 뒤 "성능과 안전을 어떻게 평가할 것인가"로 확장하는 변형에 바로 쓸 수 있다.
- **AI 보안·통제 상실**: 140회 2교시 **AI 보안**(통제 상실), 140회 1교시 **NHI**(비인간 신원)가 출제됐다. 안전 위반률·권한 준수 평가는 에이전트 통제의 측정 수단이다.
- **AI 테스트**: 140회 3교시 **메타모픽 테스트**가 출제됐다. 정답이 하나로 정해지지 않는 에이전트 평가에서 테스트 오라클 문제를 다루는 기법으로 함께 정리할 수 있다.
- **AI 리스크**: 139회 2교시 **AI 리스크**가 출제됐다. 평가 체계는 리스크를 측정해 배포 여부를 판단하는 통제 수단이다.
- **예상 변형**
  - 1교시: "AI 에이전트 평가에서 궤적(Trajectory) 평가를 설명하시오"
  - 1교시: "pass@k와 pass^k를 비교하시오"
  - 논술: "업무 자동화용 AI 에이전트 도입 시 성능·안전성 평가 체계와 배포 기준을 제시하시오"

## 5. 답안 구성 예시

**단답형**(1교시, 1페이지)
- 정의: 에이전트가 계획·도구 호출·환경 상호작용으로 과업을 수행하는 전 과정을 결과·경로·안전·비용 측면에서 측정하는 활동
- 특징 3개: ① 결과·궤적·구성요소의 다층 평가 ② 반복 실행 기반 일관성(pass^k) 측정 ③ 샌드박스에서 부작용·안전 위반 검사
- 구성도 키워드: 과업 세트 → 샌드박스 → 에이전트 k회 실행 → 궤적 로그 → 규칙·LLM 판정·사람 평가 → 지표 → 배포 게이트

**논술형(2~4교시) 목차**
1. 개요: 행동하는 AI의 확산과 에이전트 신뢰성 검증 수요
2. 구성/비교: LLM vs 에이전트 평가 비교표, 평가 하네스 구성도, 지표표
3. 적용방안: 업무 기반 자체 과업 세트 구축, 샌드박스 환경, pass^k 기준 배포 게이트, 주입 공격 시나리오 평가, 운영 궤적 재평가
4. 고려사항: 비결정성과 반복 비용, 판정자 편향, 벤치마크 오염, 환경 재현성, 평가 비용
5. 기술사 제언: 에이전트 배포 기준을 단일 성공률이 아니라 **반복 일관성과 안전 위반 0건**으로 정하고, 되돌릴 수 없는 행동은 평가 결과와 무관하게 사람 승인을 거치도록 설계할 것
