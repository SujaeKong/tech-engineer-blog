## 1. 뉴스 요약

2026-06-01 지디넷코리아·뉴시스·IT조선·테크월드·데이터넷 등은 **베스핀글로벌이 우리금융지주의 'AI 연구환경 운영 사업'을 수주**했다고 보도했다. 핵심은 ① **망분리 규제가 적용되는 금융권에서도 외부 클라우드·오픈소스·LLM 모델을 안전하게 연구·검증할 수 있는 격리 AI 샌드박스 환경**을 외주 운영 모델로 도입, ② **금융위의 망분리 완화 정책**(별도 보도 mstoday: "금융위, AI 보안 대응 본격화…망분리 완화 속 민간자문단 출범")에 따라 금융 데이터·AI 모델·GPU 인프라를 결합한 **금융 특화 AI 인프라(Private AI Platform)** 구축이 본격화되었다는 점이다. 베스핀글로벌은 우리금융 임직원이 폐쇄망 내에서 **허깅페이스·오픈소스 LLM·외부 API·벡터DB**를 안전하게 실험할 수 있도록 **데이터 라벨링 → 모델 학습 → 평가 → 모델 배포** 전 주기를 지원한다. 같은 시기 시중은행·증권사도 유사한 AI 연구환경(Innovation Sandbox)을 입찰·구축 중이어서 **금융권 AX 인프라 표준화** 흐름이 가속화되고 있다. 기술사 시스템구조 영역에서 **망분리·가상화·클라우드 분리·GPU 자원 관리·MLOps**는 출제 비중 19%의 핵심 카테고리다.

## 2. 핵심 개념

### 망분리 vs 망연계 vs AI 연구환경 분리 비교

| 항목 | 물리적 망분리 | 논리적 망분리 | AI 연구환경 분리(샌드박스) |
|---|---|---|---|
| 구성 | 별도 HW·NW 완전 분리 | VDI·CBC 등 가상화 분리 | 폐쇄 클러스터 + 통제된 외부 연계 |
| 데이터 흐름 | 일방 전송 | 통제된 양방향 | 정책 기반 데이터·모델 반입 반출 |
| 외부 모델 사용 | 불가 | 제한적 | 화이트리스트 모델·API 가능 |
| 보안 수준 | 최상 | 상 | 상 (DLP·승인·감사 결합) |
| AX 적합성 | 낮음 | 중 | 높음(연구·실험 친화) |

### 금융권 AI 샌드박스 아키텍처 구성

| 계층 | 구성요소 | 역할 |
|---|---|---|
| 격리 네트워크 | 전용 VPC, 폐쇄망 영역, 프록시 게이트웨이 | 금융망과 인터넷 영역 분리 |
| 컴퓨트 | GPU 노드(H100/H200 등), 쿠버네티스, 슬럼(SLURM) | 학습·추론 자원 풀링 |
| 데이터 | 가명·익명 데이터 레이크, 벡터DB, 메타카탈로그 | 금융 데이터 라벨링·검색 |
| 모델 | 오픈 LLM, 폐쇄형 API 미러, 모델 레지스트리 | 모델 반입·버전 관리 |
| MLOps | 실험 관리, 파이프라인, 자동 평가 | 학습·튜닝·평가 자동화 |
| 보안 | DLP·승인 워크플로·감사 로그·키 관리(KMS·HSM) | 데이터·모델 유출 통제 |
| 거버넌스 | 모델 카드, RAG 소스 추적, 윤리·편향 검토 | 신뢰성·설명 책임 확보 |

### 망분리 완화 정책 흐름

| 시점 | 정책/사건 | 영향 |
|---|---|---|
| 2024 | 금융분야 망분리 규제 단계적 완화 | SaaS·클라우드 사용 확대 |

## 3. 기술사 출제 포인트

### 개념 정의와 필요성

- **AI 연구환경(AI Sandbox)**: 금융망 격리 요건을 유지하면서 외부 LLM·오픈소스·벡터DB 등을 통제된 형태로 실험·평가·배포할 수 있는 폐쇄형 AI 플랫폼
- **망분리 완화**: 물리·논리 망분리 일률 적용에서 위험 기반·제로트러스트 통제로 전환하는 정책 흐름
- **금융권 AX(AI Transformation)**: 금융 업무에 AI 모델을 본격 도입하는 디지털전환, 신용·이상거래 탐지·고객상담·내부업무 자동화 등
- **필요성**: ① 금융 데이터의 민감성과 LLM 활용 수요의 충돌 해소, ② 외부 모델·SaaS 검증 채널 필요, ③ 망분리 비용·생산성 저하 완화, ④ 거버넌스·감독당국 보고 의무 충족

### 기존 방식과의 비교

- **전통적 폐쇄망 개발**: 외부 도구·모델 사용 불가 → AI 실험 속도·품질 저하
- **퍼블릭 클라우드 AI**: 빠른 실험 가능하나 금융 데이터 반출 위험, 규제 부적합
- **VDI 기반 망연계**: 보안 통제는 가능하나 GPU 자원·대용량 데이터 처리 한계
- **AI 연구환경(샌드박스)**: 격리망 내 GPU·데이터·모델을 결합한 통합 실험 플랫폼, 외부 모델 반입·반출은 정책으로 통제
- **외주 운영 모델(MSP)**: 베스핀글로벌 같은 전문 MSP가 GPU·MLOps 운영 위탁, 금융사는 모델·데이터에 집중

### 아키텍처 구성요소

- **격리 네트워크**: 전용 VPC, 폐쇄 서브넷, NAC, 프록시 게이트웨이로 인터넷·금융망 분리
- **GPU 컴퓨트**: 쿠버네티스 + GPU Operator, 슬럼/Ray, NVIDIA AI Enterprise, MIG 분할
- **데이터 레이어**: 가명 데이터 레이크(Iceberg/Delta), 벡터DB(Milvus/Weaviate), 메타카탈로그(DataHub)
- **모델 레이어**: 모델 레지스트리(MLflow), 오픈 LLM 로컬 서빙(vLLM·TGI), 폐쇄형 API 프록시
- **MLOps**: 실험 추적, 파이프라인(Kubeflow/Airflow), 자동 평가·A/B 테스트
- **보안 제어**: DLP, 비식별화, KMS·HSM, 비밀관리(Vault), 권한 분리(SoD), 감사 로그
- **거버넌스**: 모델 카드·RAG 소스 추적, 편향·환각 평가, 모델 위험관리(MRM) 절차

### 도입 시 고려사항

- **규제 준수**: 전자금융감독규정·금융분야 망분리 안내서·개인정보보호법·신용정보법, 감독 보고 체계 정비
- **데이터 반입·반출 통제**: 학습 데이터 가명·집계, 모델 가중치 반출 시 점검, RAG 컨텍스트 로깅
- **GPU 자원 관리**: MIG·시간분할·우선순위 큐, 비용·전력 모니터링, 사용량 챠지백
- **모델 거버넌스**: 모델 위험관리(MRM), 모델 카드, 정기 재평가·드리프트 감지, 결과 책임 트레일
- **공급망 보안**: 오픈소스 LLM 출처·라이선스·SBOM, 외부 API 의존성 관리
- **운영 모델**: 자체 운영 vs MSP 위탁, RACI 정의, 사고 대응·복구(BCM/DRP)
- **연계 정책**: 제로트러스트(ZTNA), N2SF, ISMS-P·전자금융 보안 통제와 일관성
- **인력 역량**: AI Engineer·MLOps·Data Engineer·보안 운영 인력 교차훈련
