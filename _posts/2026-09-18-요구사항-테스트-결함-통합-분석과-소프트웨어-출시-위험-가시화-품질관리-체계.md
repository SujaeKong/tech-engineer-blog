## 1. 뉴스 요약

2026-09-18 **요구사항·테스트·결함 정보를 통합 분석해 소프트웨어 출시 위험을 한눈에 확인**하는 접근이 주목받고 있다. 따로 관리되던 세 정보를 연결해 **어떤 요구사항이 검증되지 않았고, 어디에 결함이 몰려 있는지**를 드러내 출시 판단을 돕는 것이다.

이는 품질관리가 산출물 단위 점검을 넘어 **연결된 데이터 기반 의사결정**으로 진화함을 보여준다. 요구사항 추적성과 릴리스 품질 관리는 정보관리기술사 소프트웨어공학 영역의 핵심 주제다.

## 2. 핵심 개념

### 추적성(Traceability)
**요구사항 → 설계 → 테스트케이스 → 결함**을 연결해 추적하는 것이다. 추적성 매트릭스(RTM)로 누락·영향범위를 파악한다.

### 통합 분석 요소

| 요소 | 내용 |
|---|---|
| 요구사항 | 커버리지·미검증 항목 |
| 테스트 | 수행률·통과율 |
| 결함 | 밀도·심각도·잔존 |
| 판단 | 출시 위험·품질 게이트 |

### 품질관리 체계 아키텍처 관점
핵심은 **연결된 지표로 출시 위험을 정량화**하는 것이다. ① 요구사항 추적성 매트릭스로 테스트 커버리지와 미검증 요구사항을 드러내고, ② 테스트 수행률·통과율로 진척을 보며, ③ 결함 밀도·심각도·잔존 결함으로 품질을 평가하고, ④ 기준 미달 시 출시를 막는 품질 게이트를 운영한다. 이는 **감(感)이 아닌 데이터 기반 릴리스 판단**을 가능하게 한다. 관건은 데이터 정합성, 지표의 타당성, 그리고 개발 프로세스와의 통합(ALM)이다.

## 3. 기술사 출제 포인트

- 요구사항 추적성 매트릭스(RTM)와 영향범위 분석
- 테스트 커버리지·수행률·통과율 지표
- 결함 밀도·심각도·잔존 결함과 신뢰도 평가
- 릴리스 품질 게이트와 출시 위험 정량화
- ALM 도구 통합과 데이터 기반 품질 의사결정
