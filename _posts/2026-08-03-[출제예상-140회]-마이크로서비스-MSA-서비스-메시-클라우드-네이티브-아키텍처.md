## 2. 개념·정의

### MSA (Microservices Architecture)
> 하나의 애플리케이션을 **작고 독립 배포 가능한 서비스들의 집합**으로 구성. 서비스별 독립 개발·배포·확장, 장애 격리.

### 서비스 메시 (Service Mesh)
> 서비스 간 통신을 담당하는 **인프라 계층**(사이드카/eBPF). 트래픽 관리·보안(mTLS)·관측성을 애플리케이션 코드 밖에서 처리.

## 3. MSA·서비스 메시 아키텍처

```
                   ┌── API Gateway ──┐  (인증·라우팅·집계)
                   └────────┬─────────┘
        ┌──────────────┬────┴────┬──────────────┐
   ┌────▼────┐    ┌────▼────┐ ┌──▼─────┐   ┌────▼────┐
   │ 주문 SVC│    │ 결제 SVC│ │재고 SVC│   │배송 SVC │
   │ +사이드카│   │ +사이드카│ │+사이드카│   │+사이드카│  ← Service Mesh
   └────┬────┘    └────┬────┘ └──┬─────┘   └────┬────┘   (Data Plane)
        └──────── 이벤트/사가(Saga) ── mTLS ──────┘
                          │
         [Control Plane] 트래픽정책·mTLS·관측(메트릭/트레이스)
         [데이터] 서비스별 DB(Polyglot) · CQRS/이벤트소싱
```
