## 1. 뉴스 요약

뉴시스·충남일보 등(10-14)은 **ETRI가 사람이 말로 지시하면 광통신망을 자동으로 설정하는 인공지능 운용기술**을 개발했다고 보도했다. 운용자가 장비별 명령어를 일일이 입력하던 방식을, **자연어 지시 → 자동 설정**으로 바꾸려는 연구다. 보도는 제목 수준의 정보만 확인되므로, 아래에서는 이 기술이 속한 **의도기반 네트워킹**(IBN, Intent-Based Networking)의 일반 구조를 답안용으로 정리한다.

## 2. 핵심 개념

### 정의
**의도기반 네트워킹**(IBN)은 운용자가 "무엇을 원하는가(의도)"만 선언하면, 시스템이 이를 **장비 설정으로 번역·적용하고, 의도가 계속 지켜지는지 감시·교정**하는 폐루프형 네트워크 운용 방식이다(IETF RFC 9315에서 개념과 용어 정의).

### 구성도 — IBN 폐루프

```
 운용자 의도 ("A-B 구간 100G 확보, 지연 5ms 이하")
        │  자연어 / 정책
        ▼
┌──────────────────────────────┐
│ ① 의도 해석 (LLM·정책 엔진)   │ → 구조화된 의도(목표·제약·우선순위)
├──────────────────────────────┤
│ ② 의도 번역 (Intent→Config)   │ → 경로·파장·대역폭·QoS 설정안
├──────────────────────────────┤
│ ③ 사전 검증 (디지털트윈)      │ → 충돌·용량·장애 영향 시뮬레이션
├──────────────────────────────┤
│ ④ 적용 (SDN 컨트롤러)         │ → NETCONF/YANG으로 장비 배포
├──────────────────────────────┤
│ ⑤ 보증 (Assurance)            │ → 텔레메트리 감시, 의도 위반 탐지
└──────────────┬───────────────┘
               │ 위반 시 자동 교정 또는 롤백
               └──────────▶ ② 로 재진입
```

### 전통 운용 · SDN · IBN 비교

| 구분 | 전통 수동 운용 | SDN | IBN |
|---|---|---|---|
| 입력 형태 | 장비별 CLI 명령 | 컨트롤러 API·정책 | 자연어·비즈니스 의도 |
| 제어 구조 | 장비 분산 | 중앙 컨트롤러 | 컨트롤러 + 의도 엔진 |
| 설정 생성 | 사람이 직접 작성 | 프로그램이 생성 | 의도에서 자동 번역 |
| 적용 후 확인 | 사람이 점검 | 부분 모니터링 | 지속 보증(폐루프) |
| 위반 대응 | 장애 후 수동 복구 | 이벤트 기반 일부 자동 | 의도 기준 자동 교정 |
| 운용자 역량 | 장비 명령어 숙련 | 프로그래밍 | 의도·정책 설계 |
| 주요 위험 | 휴먼 에러 | 컨트롤러 단일장애점 | 의도 오해석·자동화 오작동 |

### 관련 표준·기준
- **IETF RFC 9315**: IBN 개념·용어 정의(의도, 의도 번역, 보증)
- **NETCONF/YANG**: 장비 설정을 모델 기반으로 표준화해 자동 배포를 가능하게 하는 기반
- **TM Forum 자율 네트워크 수준(L0~L5)**: 수동(L0)에서 완전 자율(L5)까지 운용 자동화 단계 구분
- **ETSI ZSM**: 무중단·무인 운용(Zero-touch)을 위한 관리 프레임워크

### 광통신망에 적용할 때의 특수성
광 전송망은 IP 패킷망과 달리 **물리 계층의 파장·경로 자원**을 다룬다. 의도 하나("대역폭 증설")가 ROADM 경로 재설정, 파장 할당, 광신호 품질(OSNR) 확인까지 이어지므로, **광 계층과 IP 계층을 함께 고려하는 다계층 번역**이 필요하다. 또 잘못된 경로 변경은 다수 회선의 동시 장애로 번질 수 있어, 적용 전 시뮬레이션과 단계적 반영이 IP망보다 더 중요하다.

### LLM을 운용에 쓸 때의 통제 장치
- LLM 출력은 **설정 초안**으로만 취급하고, 정책 엔진·디지털트윈 검증을 통과해야 반영
- 영향 범위가 큰 변경은 **사람 승인(Human-in-the-loop)** 단계 의무화
- 모든 변경에 **버전 관리·즉시 롤백** 경로 확보
- 의도 해석 결과를 운용자에게 되물어 확인(예: "A-B 구간 100G, 지연 5ms 맞습니까?")

## 3. 기술사 출제 포인트

- 의도기반 네트워킹(IBN)의 정의와 등장 배경
- IBN 폐루프 구성(의도 해석·번역·검증·적용·보증)
- SDN과 IBN의 차이와 관계
- 자연어(LLM) 기반 운용의 오해석·오작동 위험과 통제 방안
- 디지털트윈 기반 변경 사전 검증과 롤백
- 광-IP 다계층 자원(파장·경로·대역폭) 동시 제어
- NETCONF/YANG 모델 기반 설정 자동화
- 자율 네트워크 성숙도(TM Forum L0~L5)와 단계적 도입
- 의도 보증(Assurance)을 위한 텔레메트리·SLA 감시

## 4. 연결 기출 토픽과 예상 변형

- **SDN**: 블로그 통합 기출 분석(`exam_trend_integrated.json`) 기준 기출 6회 등장한 네트워크 빈출 토픽이다. IBN은 SDN 위에 의도 계층을 얹은 구조라, "SDN과 IBN 비교"는 SDN 기출을 자연스럽게 확장한 형태다.
- **QoS 큐잉**: 140회 2교시에 **FIFO vs 가중 공정 큐잉**(WFQ)이 출제됐다. "지연 5ms 이하" 같은 의도는 결국 큐잉·스케줄링 정책으로 번역되므로, 의도 번역의 구체 사례로 연결할 수 있다.
- **주소 설계**: 139회 4교시 **서브네팅·슈퍼네팅·VLSM**처럼 기본기 문항이 꾸준히 나온다. 140회 분석에서도 네트워크 영역은 시사 키워드보다 **기본기(부호화·큐잉·다중접속)** 위주로 출제됐다.
- **예상 변형**
  - 1교시: "의도기반 네트워킹(IBN)의 개념과 구성요소를 설명하시오"
  - 논술: "LLM 기반 네트워크 운용 자동화의 구조와 도입 시 위험 및 통제 방안을 논하시오"
  - 융합: SDN·NFV 기본 구조를 먼저 쓰게 한 뒤 IBN으로 확장하는 2단 문항

## 5. 답안 구성 예시

**단답형(1교시, 1페이지)**
- 정의: 의도를 선언하면 번역·적용·보증까지 자동 수행하는 폐루프 운용 방식(RFC 9315)
- 특징 3개: ① 의도 중심 선언형 ② 지속 보증·자동 교정 ③ SDN 컨트롤러 기반 적용
- 구성도 키워드: 의도 해석 → 번역 → 검증 → 적용 → 보증 → (교정 루프)

**논술형(2~4교시) 목차**
1. 개요: 수동 운용의 한계(휴먼 에러, 변경 지연)와 IBN 등장 배경
2. 구성: 폐루프 5단계 구성도 + 전통·SDN·IBN 비교표
3. 적용방안: 광-IP 다계층 번역, 디지털트윈 사전 검증, NETCONF/YANG 배포
4. 고려사항: LLM 오해석, 자동화 연쇄 장애, 보안(컨트롤러·API 보호)
5. 기술사 제언: TM Forum L2→L3 단계적 도입, 고위험 변경은 사람 승인 유지, 롤백 체계를 자동화보다 먼저 갖출 것
