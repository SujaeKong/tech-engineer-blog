## 1. 뉴스 요약

파이낸셜뉴스(11-24)는 [글로벌AI브리핑]에서 **오픈AI와 시스코가 정식 패치가 나오기 전까지 서버 보안을 지키는 AI 기술을 공개**했다고 전했다. 아시아투데이(11-25)는 FBI에 이어 CIA·국가정보국까지 해킹 피해를 입은 미국 정부기관의 보안 상황을 보도했다. 취약점이 공개되면 공격자는 며칠, 때로는 몇 시간 안에 악용을 시작하지만, 조직이 시험을 거쳐 패치를 적용하기까지는 훨씬 오래 걸린다. 공개된 기술의 구체 동작은 제목 이상으로 확인되지 않으므로, 아래에서는 **패치 관리 체계와 그 공백을 메우는 가상 패치**를 정리한다.

## 2. 핵심 개념

### 정의
**패치 관리**(Patch Management)는 소프트웨어·펌웨어의 보안 결함을 고치는 업데이트를 **식별·평가·시험·배포·검증하는 일련의 관리 활동**이다. **가상 패치**(Virtual Patching)는 원본 코드를 고치지 않고 **앞단의 보안 계층에서 해당 취약점으로 들어오는 공격 경로를 차단**하는 임시 보호 조치로, 정식 패치를 적용하기 전까지의 노출을 줄이는 **보완 통제**에 해당한다.

### 취약점 노출 기간

```
 [취약점 존재] ─▶ [공개·CVE 등록] ─▶ [벤더 패치 배포] ─▶ [조직 적용 완료]
                        │                  │                    │
   제로데이 구간 ──────┘                  │                    │
   (패치 없음)          └─ 공격 코드 등장(수시간~수일) ─┐       │
                                           │            │       │
                                           └── 조직 내부 노출 구간 ──┘
                                               (시험·승인·배포 대기)
                                                    ▲
                                       가상 패치로 이 구간을 보호
```

공격자는 공개된 패치를 원래 코드와 비교해(패치 디핑) 취약점 위치를 빠르게 찾아낸다. 그래서 **패치 공개 직후가 오히려 가장 위험한 시기**가 될 수 있다. 가상 패치는 제로데이 구간(벤더 패치 전)과 조직 내부 노출 구간(적용 전) 모두에서 쓰인다.

### 구성도 ① — 패치 관리 생명주기

```
 [1. 자산 식별]    서버·단말·네트워크 장비·SW·라이브러리 목록, 담당자·중요도
     │
     ▼
 [2. 취약점 수집]  벤더 공지 · CVE · 위협 인텔리전스 · 스캐너 결과
     │
     ▼
 [3. 우선순위]     심각도(CVSS) × 악용 가능성(실제 악용 여부·악용 예측) × 자산 중요도·노출도
     │
     ▼
 [4. 시험]         호환성·성능 영향 시험(시험 환경) · 롤백 계획
     │            ※ 긴급 시: 가상 패치 먼저 적용 후 시험 병행
     ▼
 [5. 배포]         단계적 배포(파일럿 → 전체) · 유지보수 시간 조정
     │
     ▼
 [6. 검증]         적용 여부 재스캔 · 장애 모니터링
     │
     ▼
 [7. 예외 관리]    패치 불가 자산 → 보완 통제(가상 패치·격리) 문서화·기한 관리
```

### 가상 패치 수단 비교

| 수단 | 적용 위치 | 원리 | 장점 | 한계 |
|---|---|---|---|---|
| WAF 규칙 | 웹 애플리케이션 앞단 | 취약점 공격 패턴의 HTTP 요청 차단 | 웹 취약점에 즉시 적용 | 우회 공격, 오탐 |
| IPS 시그니처 | 네트워크 경로 | 공격 트래픽 패턴 차단 | 다수 서버 일괄 보호 | 암호화 트래픽 한계 |
| RASP | 애플리케이션 런타임 내부 | 실행 중 위험 동작(명령 실행 등) 차단 | 맥락 기반 정확도 높음 | 성능 부담, 언어·플랫폼 의존 |
| 설정 차단 | 대상 시스템 | 취약 기능·모듈·포트 비활성화 | 확실한 차단 | 업무 기능 영향 |
| 접근 제한·격리 | 네트워크 분리 계층 | 취약 시스템 접근 출발지 제한, 마이크로세그먼테이션 | 공격 표면 축소 | 내부 위협에는 약함 |
| 커널 수준 필터 | 운영체제 | 특정 시스템 호출·패킷 필터 | 재부팅 없이 적용 | 운영 전문성 필요 |

### 정식 패치 vs 가상 패치

| 구분 | 정식 패치 | 가상 패치 |
|---|---|---|
| 해결 방식 | 취약 코드 자체 수정 | 공격 경로 차단 |
| 적용 속도 | 시험·승인으로 느림 | 규칙 배포로 빠름 |
| 근본 해결 | 예 | 아니오(임시 보호) |
| 서비스 영향 | 재시작·호환성 위험 | 대체로 적음(오탐 시 영향) |
| 적용 대상 | 패치가 존재하는 시스템 | 패치 없음·패치 불가 시스템 포함 |
| 관리 부담 | 배포 후 종료 | 규칙 유지·해제 관리 필요 |

가상 패치는 **패치를 대신하는 것이 아니라 시간을 버는 것**이다. 규칙이 계속 쌓이면 오탐과 성능 저하가 늘고 무엇을 보호하는지 잊히는 **보안 부채**가 되므로, 정식 패치 적용 후에는 규칙을 해제하는 기한 관리가 필요하다.

### 레거시·OT 환경
- **패치 불가 시스템**: 지원 종료 OS, 인증 때문에 변경할 수 없는 의료기기·제어 시스템은 정식 패치가 불가능하거나 오래 걸린다.
- **가용성 우선**: 공장·발전 설비는 재시작 자체가 큰 비용이라 정기 정비 기간에만 패치한다.
- **보완 통제 조합**: 네트워크 분리, 허용 목록 기반 실행 통제, 산업용 IPS를 겹쳐 노출을 줄인다.

### 구성도 ② — AI를 활용한 긴급 대응 흐름

```
 [취약점 공지]  CVE·벤더 권고문 발표
      │
      ▼
 [AI 분석]  권고문·패치 차이 분석 → 공격 조건·입력 패턴 요약
      │
      ▼
 [영향 판단]  자산 목록과 대조 → 영향받는 시스템·노출 경로 식별
      │
      ▼
 [가상 패치 초안]  WAF·IPS 규칙 초안 자동 생성
      │
      ▼
 [사람 검토·시험]  공격 재현 시험 · 정상 트래픽 오탐 확인 → 배포
      │
      ▼
 [정식 패치 적용 후]  규칙 해제·정리
```

AI는 권고문 해석과 규칙 초안 작성 시간을 줄여 줄 수 있다. 다만 잘못된 규칙은 정상 서비스를 막거나 공격을 놓치므로, **사람의 검토와 시험을 거친 뒤 배포**하는 절차가 필요하다.

### 관련 기준
- **NIST SP 800-40**: 전사 패치 관리 계획 가이드
- **ISMS-P**: 패치 관리, 취약점 점검·조치 통제 항목
- **CISA KEV 목록**: 실제 악용이 확인된 취약점 목록 — 우선순위 근거
- **CVSS·EPSS**: 취약점 심각도와 악용 가능성 예측 점수
- **IEC 62443**: 산업 제어 시스템의 패치·보완 통제 요구

## 3. 기술사 출제 포인트

- 패치 관리와 가상 패치의 정의(보완 통제)
- 취약점 노출 기간(제로데이 구간·조직 내부 노출 구간)과 패치 디핑
- 패치 관리 생명주기(자산 식별→수집→우선순위→시험→배포→검증→예외)
- 우선순위 결정(CVSS·실제 악용 여부·악용 예측·자산 중요도)
- 가상 패치 수단(WAF·IPS·RASP·설정 차단·격리) 비교
- 정식 패치와 가상 패치 비교(근본 해결 vs 시간 확보)
- 가상 패치 규칙의 보안 부채화와 해제 관리
- 레거시·OT의 패치 불가 환경과 보완 통제
- AI 기반 권고문 분석·규칙 초안 생성과 사람 검토

## 4. 연결 기출 토픽과 예상 변형

- **CTEM**: 139회 1교시에 **CTEM**(지속적 위협 노출 관리)이 출제됐다. 노출 식별·우선순위·검증·동원으로 이어지는 CTEM의 마지막 실행 단계가 패치와 가상 패치다.
- **정보보호 컴플라이언스**: 140회 4교시에 **정보보호 컴플라이언스**가 출제됐다. 패치 예외와 보완 통제의 문서화는 인증 심사의 단골 점검 항목이다.
- **SW 공급망**: 140회 2교시에 **오픈소스 라이선스와 SW 공급망**이 출제됐다. 오픈소스 라이브러리 취약점은 패치 관리 대상 자산 목록(SBOM)과 연결된다.
- **예상 변형**
  - 1교시: "가상 패치(Virtual Patching)를 설명하시오"
  - 1교시: "RASP(Runtime Application Self-Protection)와 WAF를 비교하시오"
  - 논술: "취약점 공개부터 조치 완료까지의 노출 기간을 줄이기 위한 패치 관리 체계를 제시하시오"

## 5. 답안 구성 예시

**단답형**(1교시, 1페이지)
- 정의: 원본 코드를 고치지 않고 앞단 보안 계층에서 취약점 공격 경로를 차단하는 임시 보완 통제
- 특징 3개: ① 정식 패치 전 노출 구간 보호 ② WAF·IPS·RASP·설정 차단 등 다양한 수단 ③ 근본 해결이 아니므로 해제 기한 관리 필요
- 구성도 키워드: 취약점 공개 → 공격 코드 등장 → [가상 패치 보호] → 정식 패치 적용 → 규칙 해제

**논술형(2~4교시) 목차**
1. 개요: 취약점 악용 속도와 패치 적용 지연의 격차
2. 구성/비교: 노출 기간 구성도, 패치 관리 생명주기, 가상 패치 수단 비교표, 정식 vs 가상 패치 비교표
3. 적용방안: 자산·SBOM 기반 영향 판단, 악용 가능성 중심 우선순위, 긴급 가상 패치 절차, 레거시·OT 보완 통제, AI 권고문 분석
4. 고려사항: 가상 패치 오탐과 우회, 규칙 누적에 따른 보안 부채, 시험 환경 부족, AI 규칙 검증
5. 기술사 제언: 패치 관리 성과를 적용률이 아니라 **실제 악용 취약점의 노출 기간**으로 측정하고, 가상 패치는 해제 기한이 있는 예외로 관리해 영구 우회책이 되지 않게 할 것
