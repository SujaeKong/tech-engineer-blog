## 1. 뉴스 요약

뉴시스·조선비즈·머니투데이·헤럴드경제 등(10-21)은 **SK쉴더스·이노비즈협회·DB손해보험이 중소기업 사이버보안과 사이버보험을 연계 지원**하는 협약을 맺었다고 보도했다. 한국경제(10-20)는 이를 **"보안 예방부터 사고 대응·손실 보상까지" 원스톱 사이버위험 관리체계**로 소개했고, 데일리안(10-21)은 **보험과 관제를 묶은 지원**이라는 점에 주목했다. 같은 시기 뉴시스(10-20)는 **중소·중견기업 86%가 사이버 침해 피해를 겪었다**는 조사를, 매일경제 등(10-21)은 경기도경제과학진흥원의 **기업당 최대 360만 원 보안 지원**을 전했다. 협약의 세부 상품 구성은 보도 제목 이상으로 확인되지 않으므로, 아래에서는 보안과 보험을 묶는 **사이버 리스크 관리 구조**를 답안 재료로 정리한다.

## 2. 핵심 개념

### 정의
**사이버보험**은 해킹·랜섬웨어·정보유출 등 사이버 사고로 생긴 **자기 손해와 제3자 배상책임을 금전적으로 보전**하는 보험으로, 위험관리의 4가지 처리 전략(회피·감소·전가·수용) 중 **위험 전가**(Transfer)에 해당한다. 보험은 사고 확률을 낮추지 못하므로, 보안 통제(위험 감소)와 결합해야 잔여 위험을 감당 가능한 수준으로 만들 수 있다.

### 구성도 — 보안·보험 연계 사이버위험 관리 흐름

```
 [위험 식별·평가]  자산 식별 → 위협·취약점 분석 → 위험도 산정
        │
        ▼
 [위험 처리 결정] ─┬─ 회피: 위험 업무·시스템 중단
                  ├─ 감소: 백업·MFA·패치·EDR·보안관제  ← 보안기업
                  ├─ 전가: 사이버보험·외주 계약 조항    ← 보험사
                  └─ 수용: 잔여 위험 경영진 승인
        │
        ▼
 [보험 인수(Underwriting)]  보안 수준 진단 결과 → 가입 여부·보험료·보상한도 결정
        │
        ▼
 [사고 발생]  관제 탐지 → 초동 대응·포렌식 → 복구 → 보험금 청구·손해사정
        │
        └──▶ 사고 원인 분석 결과를 다음 위험평가와 보험 갱신에 반영(피드백)
```

보안기업은 **감소**를, 보험사는 **전가**를 맡고, 둘이 진단 결과를 공유하면 "보안을 잘할수록 보험료가 내려가는" 구조가 생긴다. 보안·보험 연계가 노리는 효과가 바로 이 투자 유인이다.

### 위험 처리 4전략 비교

| 전략 | 의미 | 사이버 보안 예시 | 비용 성격 | 한계 |
|---|---|---|---|---|
| 회피(Avoid) | 위험 원인 제거 | 불필요한 외부 서비스 폐쇄 | 사업 기회 상실 | 핵심 업무는 회피 불가 |
| 감소(Mitigate) | 발생 가능성·영향 축소 | MFA·백업·패치·관제 | 보안 투자 | 위험 0은 불가능 |
| 전가(Transfer) | 손실 부담을 제3자에게 이전 | 사이버보험·위탁 계약 책임 조항 | 보험료 | 평판·고객 신뢰 손실은 전가 불가 |
| 수용(Accept) | 위험 인지 후 감내 | 저영향 자산의 잔여 위험 | 사고 시 직접 부담 | 경영진 승인·문서화 필요 |

### 사이버보험이 보상하는 손해 유형

| 구분 | 담보 내용 | 비고 |
|---|---|---|
| 자기 손해(1st party) | 사고 조사·포렌식 비용 | 원인 규명 |
| 자기 손해 | 데이터·시스템 복구 비용 | 랜섬웨어 대응 핵심 |
| 자기 손해 | 사업 중단 손실(영업 손실) | 대기 기간·면책 조건 확인 |
| 배상책임(3rd party) | 정보주체·거래처 손해배상 | 소송 비용 포함 여부 |
| 배상책임 | 규제 대응 비용 | 과징금 보상은 법률상 제한될 수 있음 |
| 대응 지원 | 위기 커뮤니케이션·통지 비용 | 유출 통지 의무 이행 |

### 중소기업에 연계 모델이 필요한 이유
- **보안 인력 부재**: 위험평가를 스스로 할 수 없어, 보험 가입 진단이 사실상 첫 보안 점검이 된다.
- **사고 후 생존 문제**: 대기업은 복구 비용을 흡수하지만 중소기업은 영업 중단 한 번이 존폐로 이어진다. 손실 보상과 복구 지원이 함께 와야 한다.
- **정보 비대칭 해소**: 보험사는 기업의 보안 수준을 알기 어렵고(역선택), 가입 후 보안을 소홀히 할 우려(도덕적 해이)도 있다. 관제 데이터 공유가 이 문제를 줄인다.

### 관련 법·표준
- **개인정보 보호법 제39조의9**(손해배상책임의 보장): 일정 규모 이상의 개인정보처리자는 보험 가입·준비금 적립 등으로 손해배상책임을 보장해야 한다(대상·최저 금액은 시행령).
- **ISO/IEC 27005**: 정보보안 위험관리 지침 — 위험 처리 옵션으로 수정(감소)·유지(수용)·회피·공유(전가)를 제시
- **ISO 31000**: 전사 위험관리 원칙·프레임워크
- **ISMS-P**: 위험평가와 위험 처리 계획 수립을 인증 기준으로 요구

## 3. 기술사 출제 포인트

- 위험 처리 4전략(회피·감소·전가·수용)과 사이버보험의 위치
- 보안 수준 진단과 보험료 연동(Underwriting) 구조
- 사이버보험 담보 유형(자기 손해·배상책임·대응 지원)
- 보험으로 전가할 수 없는 위험(평판·신뢰·데이터 자체)
- 역선택·도덕적 해이와 보안 데이터 공유를 통한 완화
- 중소기업 보안 사각지대와 관제·보험 통합 지원 모델
- 개인정보 보호법 손해배상책임 보장 의무
- 사고 대응 절차(탐지·포렌식·복구·청구)와 피드백
- ISO/IEC 27005·ISMS-P 위험평가와의 연계
- 랜섬웨어 몸값 보상·전쟁 면책 등 사이버보험 쟁점

## 4. 연결 기출 토픽과 예상 변형

- **위험 대응 전략**: 139회 1교시에 **IT 프로젝트 부정적 위험과 대응 전략**이 출제됐다. 회피·전가·완화·수용이라는 같은 틀을 프로젝트가 아닌 **사이버 위험**에 적용하면 이 뉴스가 그대로 사례가 된다.
- **컴플라이언스**: 140회 4교시 **정보보호 컴플라이언스**(개념·필요성·대응)가 출제됐다. 손해배상책임 보장 의무는 컴플라이언스 항목의 구체 예시로 쓸 수 있다.
- **사고 대응**: 140회 1교시 **디지털 포렌식**, 139회 1교시 **CTEM**(지속적 위협 노출 관리)도 출제됐다. 보험금 청구는 포렌식 결과를 근거로 하므로, 사고 대응 흐름 속에서 함께 설명하기 좋다.
- **예상 변형**
  - 1교시: "사이버보험의 개념과 위험관리에서의 역할을 설명하시오"
  - 1교시: "위험 처리 전략(회피·감소·전가·수용)을 정보보안 사례로 설명하시오"
  - 논술: "중소기업의 사이버 위험 관리 체계를 예방·대응·보상 관점에서 제시하시오"

## 5. 답안 구성 예시

**단답형**(1교시, 1페이지)
- 정의: 사이버 사고의 자기 손해·배상책임을 보전하는 보험, 위험 처리 전략 중 전가
- 특징 3개: ① 보안 수준 기반 인수·보험료 차등 ② 자기 손해+배상책임+대응 지원 담보 ③ 위험 감소 통제와 결합해야 효과
- 구성도 키워드: 위험평가 → 처리 전략 결정 → 보안 진단 기반 인수 → 사고 대응 → 청구 → 피드백

**논술형(2~4교시) 목차**
1. 개요: 중소기업 침해 피해 확산과 "예방만으로는 부족한" 사고 이후 생존 문제
2. 구성/비교: 위험 처리 4전략 비교표, 보안·보험 연계 흐름 구성도, 담보 유형표
3. 적용방안: 보험 가입 진단을 보안 점검으로 활용, 관제-보험사 데이터 공유, 정부 보안 지원사업과 결합
4. 고려사항: 전가 불가 위험, 역선택·도덕적 해이, 면책 조항(전쟁·미패치 취약점), 랜섬웨어 몸값 보상 논란
5. 기술사 제언: 보험을 보안의 대체재가 아닌 **잔여 위험 처리 수단**으로 위치시키고, 보안 통제 수준과 보험료를 연동해 투자 유인을 만들 것
