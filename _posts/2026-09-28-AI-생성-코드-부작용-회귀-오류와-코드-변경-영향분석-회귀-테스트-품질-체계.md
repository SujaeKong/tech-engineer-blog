## 1. 뉴스 요약

2026-09-28 **"AI가 만든 기능은 작동해도 다른 기능에 오류를 낸다"**며, AI 코딩 도구 사용 시 **코드 변경 범위부터 검사해야 한다**는 지적이 나왔다. 요청한 기능은 잘 동작하지만, AI가 관련 없는 코드까지 수정하거나 공유 모듈을 바꿔 **기존 기능이 깨지는(회귀)** 사례가 늘고 있다는 것이다.

이는 AI 코딩 시대에 품질 관리의 초점이 **새 기능 검증에서 변경 영향 통제**로 옮겨가야 함을 보여준다. 변경 영향분석과 회귀 테스트는 정보관리기술사 소프트웨어공학 영역의 핵심 주제다.

## 2. 핵심 개념

### 회귀 결함(Regression Defect)
기존에 정상 동작하던 기능이 **다른 변경의 부작용으로 깨지는 결함**이다. AI는 한 번에 넓은 범위를 수정하는 경향이 있어 회귀 위험이 크다.

### 변경 통제 요소

| 요소 | 내용 |
|---|---|
| 범위 검사 | diff 크기·수정 파일 확인 |
| 영향분석 | 의존성·호출관계 추적 |
| 회귀 테스트 | 영향 영역 우선 재시험 |
| 리뷰 | 사람 검토·승인 게이트 |

### 변경 영향분석 품질 체계 관점
핵심은 **변경을 작고 추적 가능하게 유지**하는 것이다. ① AI 변경의 diff 범위를 먼저 확인해 요청 외 수정을 걸러내고, ② 호출 그래프·의존성으로 영향받는 모듈을 식별하며, ③ 영향 영역을 우선하는 회귀 테스트 선택(RTS)으로 효율적으로 재시험하고, ④ 사람 리뷰와 CI 품질 게이트로 병합을 통제한다. **작은 단위 커밋과 명확한 작업 지시**가 AI 변경의 예측가능성을 높인다. 관건은 테스트 커버리지, 영향분석 자동화, 그리고 리뷰 부담 관리다.

## 3. 기술사 출제 포인트

- 회귀 결함의 개념과 AI 생성 코드의 회귀 위험
- 변경 영향분석(의존성·호출관계·추적성)
- 회귀 테스트 선택(RTS)·우선순위화 기법
- 형상관리·변경관리와 작은 단위 커밋 원칙
- CI 품질 게이트·코드 리뷰와 AI 코딩 거버넌스
