## 1. 뉴스 요약

뉴스웨이(11-18)는 **SK쉴더스가 "사이버 침해사고가 2년 새 2.3배 늘었다"며 MDR 기반 대응 역량을 강화**한다고 보도했다. 같은 시기 이데일리(11-17)는 AI 해킹 위협이 커지는 가운데 **행정안전부의 지방정부 사이버보안 예산이 줄었다**고 전했다. 공격은 늘고 빨라지는데 보안 인력과 예산은 제한돼 있어, **탐지부터 대응까지를 외부 전문 조직에 맡기는 관리형 탐지·대응**(MDR)이 대안으로 떠오르고 있다. 보고서의 집계 기준과 SK쉴더스 서비스의 세부 내용은 제목 이상으로 확인되지 않으므로, 아래에서는 **보안관제 운영 모델과 MDR의 구조**를 정리한다.

## 2. 핵심 개념

### 정의
**MDR**(Managed Detection and Response, 관리형 탐지·대응)은 외부 전문 조직이 고객 환경의 엔드포인트·네트워크·클라우드 텔레메트리를 **24시간 분석해 위협을 탐지하고, 조사와 초기 대응(격리·차단)까지 직접 수행**하는 서비스다. 경보를 전달하는 데 그치는 전통적 관제와 달리 **"대응"까지 책임 범위에 포함**한다는 점이 핵심 차이이며, 위협 헌팅(Threat Hunting)으로 탐지 규칙에 걸리지 않는 공격도 능동적으로 찾는다.

### 보안관제 운영 모델 비교

| 구분 | 자체 SOC | MSSP(관리형 보안 서비스) | MDR |
|---|---|---|---|
| 운영 주체 | 조직 내부 인력 | 외부 사업자 | 외부 전문 대응 조직 |
| 주 역할 | 탐지·분석·대응 전 과정 | 보안 장비 운영·모니터링·경보 전달 | 탐지·조사·대응·헌팅 |
| 대응 범위 | 직접 수행 | 경보 통보 후 고객이 대응 | 사전 승인 범위에서 직접 격리·차단 |
| 데이터 기반 | SIEM 중심 | 장비 로그(방화벽·IPS 등) | EDR·XDR 텔레메트리 중심 |
| 위협 헌팅 | 역량에 따라 다름 | 제한적 | 기본 서비스 |
| 비용 구조 | 인력·시스템 고정비 큼 | 장비·관제 계약 | 자산(엔드포인트) 수 기반 구독 |
| 장점 | 내부 맥락 이해, 통제력 | 장비 운영 부담 감소 | 빠른 대응, 전문 인력 확보 |
| 한계 | 24시간 인력 확보 어려움 | 경보 피로, 대응 지연 | 내부 맥락 부족, 외부 의존 |

현실에서는 하나만 고르기보다 **자체 SOC가 정책·의사결정을 맡고 MDR이 야간·주말 탐지와 초기 대응을 맡는 혼합형**이 많다.

### 탐지 기술 비교

| 구분 | EDR | NDR | XDR |
|---|---|---|---|
| 수집 위치 | 단말(PC·서버) | 네트워크 트래픽 | 단말·네트워크·클라우드·메일·ID 통합 |
| 강점 | 프로세스·파일 행위 상세 추적, 단말 격리 | 에이전트 없는 장비·내부 확산 탐지 | 여러 계층 신호 연계로 공격 흐름 파악 |
| 약점 | 에이전트 미설치 장비 사각지대 | 암호화 트래픽 내용 확인 한계 | 벤더 통합 수준에 따라 효과 차이 |
| 대응 수단 | 프로세스 종료·단말 격리 | 세션 차단 | 계층별 자동 대응 연동 |

### 구성도 ① — MDR 서비스 흐름

```
 [고객 환경]  엔드포인트 · 서버 · 클라우드 · 메일 · ID(계정)
      │  EDR/XDR 에이전트 · 로그 수집
      ▼
 [MDR 플랫폼]  텔레메트리 수집 → 탐지 규칙 · 행위 분석 · 위협 인텔리전스 매칭
      │
      ▼
 [분석가 1차 분류]  오탐 제거 · 심각도 판정
      │
      ▼
 [조사]  공격 범위 · 침투 경로 · 영향 자산 확인(타임라인 재구성)
      │
      ├──▶ [대응]  사전 승인 범위: 단말 격리 · 계정 정지 · 악성 프로세스 종료
      │            범위 밖: 고객 담당자 즉시 연락 → 승인 후 조치
      ▼
 [보고·복구 지원]  사고 보고서 · 재발 방지 권고 · 탐지 규칙 개선
      ▲
 [위협 헌팅]  가설 기반 능동 탐색 → 새 탐지 규칙
```

### 사전 승인 대응(Pre-authorized Response)
MDR의 대응 속도는 **고객이 미리 어떤 조치를 허락해 두었는가**에 달려 있다. 랜섬웨어는 침투 후 짧은 시간 안에 암호화를 시작하므로, 야간에 담당자 승인을 기다리다 보면 피해가 커진다.
- **자동 허용**: 일반 업무 PC 격리, 악성 파일 삭제
- **조건부 허용**: 서버 격리는 업무 영향이 크므로 서비스 중요도에 따라 결정
- **승인 필수**: 핵심 업무 시스템 차단, 관리자 계정 정지

이 범위를 계약서와 대응 절차서(플레이북)에 명시해야 한다.

### 구성도 ② — 책임 분담 모델

```
 ┌────────────── 고객 조직 ──────────────┐
 │ 보안 정책·위험 수용 결정 · 자산 목록     │
 │ 사전 승인 범위 결정 · 복구·사업 연속성   │
 │ 법적 신고·대외 커뮤니케이션              │
 └───────────────┬───────────────────────┘
                 │ 협업(연락 체계·플레이북·정기 회의)
 ┌───────────────┴───────────────────────┐
 │ MDR 사업자                              │
 │ 24시간 탐지·분석 · 조사 · 초기 대응      │
 │ 위협 헌팅 · 탐지 규칙 관리 · 보고         │
 └───────────────────────────────────────┘
```

**탐지와 초기 대응은 맡길 수 있어도, 침해사고 책임과 법적 신고 의무는 고객에게 남는다.** MDR 도입이 보안 책임 이전을 뜻하지 않는다는 점을 답안에서 짚어 두면 좋다.

### 성과 지표
- **MTTD**(평균 탐지 시간): 침투부터 탐지까지
- **MTTR**(평균 대응 시간): 탐지부터 격리·차단까지
- **오탐률·경보 대비 실제 사고 비율**: 고객에게 전달되는 경보의 품질
- **커버리지**: 에이전트가 설치된 자산 비율 — 사각지대 확인
- **헌팅 성과**: 헌팅으로 발견한 위협과 새로 만든 탐지 규칙 수

### 도입 시 고려사항
- **데이터 주권·개인정보**: 텔레메트리가 외부(해외 포함)로 전송되는지, 보관 기간과 접근 통제
- **커버리지 사각지대**: 에이전트를 설치할 수 없는 OT·레거시 장비는 NDR 등으로 보완
- **내부 역량 유지**: 외부 의존이 커지면 내부가 공격 맥락을 잃는다. 정기 보고 회의와 공동 훈련 필요
- **종료 시 전환**: 계약 종료 시 탐지 규칙·로그·사고 이력을 넘겨받는 조항

### 관련 기준
- **NIST SP 800-61**: 컴퓨터 보안 사고 대응 가이드
- **NIST CSF 2.0**: 식별·보호·탐지·대응·복구 기능에 거버넌스 추가
- **ISO/IEC 27035**: 정보보안 사고 관리
- **ISMS-P**: 침해사고 대응 절차·모니터링 통제 항목
- **정보통신망법**: 침해사고 발생 시 신고 의무

## 3. 기술사 출제 포인트

- MDR의 정의와 탐지·조사·대응을 포함하는 책임 범위
- 자체 SOC·MSSP·MDR 운영 모델 비교
- EDR·NDR·XDR 탐지 기술 비교
- MDR 서비스 흐름(수집→탐지→분류→조사→대응→보고)
- 사전 승인 대응과 플레이북
- 위협 헌팅(가설 기반 능동 탐색)
- 고객–MDR 책임 분담과 법적 신고 의무
- MTTD·MTTR·커버리지 등 성과 지표
- 데이터 주권·사각지대·내부 역량 유지 등 도입 고려사항

## 4. 연결 기출 토픽과 예상 변형

- **CTEM**: 139회 1교시에 **CTEM**(지속적 위협 노출 관리)이 출제됐다. CTEM이 노출을 줄이는 예방 축이라면, MDR은 뚫린 뒤 빠르게 찾고 막는 탐지·대응 축으로 짝을 이룬다.
- **디지털 포렌식**: 140회 1교시에 **디지털 포렌식**이 출제됐다. MDR의 조사 단계(타임라인 재구성)와 증거 보존이 바로 이어진다.
- **정보보호 컴플라이언스**: 140회 4교시에 **정보보호 컴플라이언스**가 출제됐다. 외부 위탁 시 책임 분담과 신고 의무를 컴플라이언스 관점으로 정리할 수 있다.
- **NHI**: 140회 1교시 **NHI**(비인간 신원)가 출제됐다. XDR이 ID 신호를 통합하는 흐름에서 서비스 계정·API 키 오남용 탐지로 연결된다.
- **예상 변형**
  - 1교시: "MDR(Managed Detection and Response)을 설명하시오"
  - 1교시: "EDR과 XDR을 비교하시오"
  - 논술: "보안 인력이 부족한 조직의 침해사고 탐지·대응 체계 구축 방안을 운영 모델 비교와 함께 제시하시오"

## 5. 답안 구성 예시

**단답형**(1교시, 1페이지)
- 정의: 외부 전문 조직이 텔레메트리를 24시간 분석해 위협을 탐지하고 조사·초기 대응까지 수행하는 관리형 서비스
- 특징 3개: ① 경보 전달을 넘어 사전 승인 범위 내 직접 대응 ② EDR·XDR 텔레메트리 기반 ③ 위협 헌팅 기본 제공
- 구성도 키워드: 수집 → 탐지 → 1차 분류 → 조사 → 대응(사전 승인) → 보고 / 위협 헌팅

**논술형(2~4교시) 목차**
1. 개요: 침해사고 급증과 보안 인력·예산 제약, MDR 부상
2. 구성/비교: 운영 모델 비교표, 탐지 기술 비교표, MDR 흐름도, 책임 분담도
3. 적용방안: 혼합형(자체 SOC + MDR) 구성, 사전 승인 범위와 플레이북, XDR로 커버리지 확대, 공동 훈련, 성과 지표 기반 계약
4. 고려사항: 데이터 주권·개인정보, OT·레거시 사각지대, 내부 역량 공동화, 계약 종료 시 전환
5. 기술사 제언: MDR 계약을 경보 건수가 아닌 **MTTD·MTTR과 커버리지 목표**로 맺고, 탐지·대응은 맡기되 위험 수용과 신고 판단은 조직 내부에 남겨 책임 공백이 없도록 할 것
