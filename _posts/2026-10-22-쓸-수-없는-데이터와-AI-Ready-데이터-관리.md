## 1. 뉴스 요약

지디넷코리아(10-20)는 "**AI는 '더러운 데이터'보다 '쓸 수 없는 데이터'에서 실패한다**"는 제목으로, AI 프로젝트의 실패 원인을 데이터 품질 자체보다 **데이터 활용 가능성** 쪽에서 짚었다. 오류가 있는 데이터는 정제하면 되지만, 어디 있는지 모르거나 의미를 해석할 수 없거나 권한 문제로 꺼낼 수 없는 데이터는 정제 단계까지 가지도 못한다는 문제의식이다. 기사 본문은 제목 수준만 확인되므로, 아래에서는 이 주장이 가리키는 **AI-Ready 데이터** 관리의 일반 구조를 답안 재료로 정리한다.

## 2. 핵심 개념

### 정의
**AI-Ready 데이터**는 정확성 같은 내재 품질뿐 아니라 **발견 가능성·이해 가능성·접근 가능성·신뢰 가능성**을 갖춰, AI 학습·추론에 즉시 투입할 수 있는 상태의 데이터를 말한다. 반대로 저장은 되어 있으나 메타데이터·소유자·권한 정보가 없어 활용되지 못하는 데이터가 "**쓸 수 없는 데이터**"이며, 이런 데이터가 쌓인 레이크를 **데이터 스웜프**(Data Swamp)라고 부른다.

### 구성도 — 데이터가 AI에 도달하기까지의 관문

```
 [원천 시스템]  ERP · CRM · 로그 · 문서 · IoT
       │
       ▼
 ┌──────────── 관문 1: 찾을 수 있는가 (Findable) ────────────┐
 │  데이터 카탈로그 · 비즈니스 용어집 · 검색 인덱스            │
 ├──────────── 관문 2: 이해할 수 있는가 (Understandable) ────┤
 │  기술/비즈니스 메타데이터 · 표준 코드 · 단위·기준일 명세     │
 ├──────────── 관문 3: 꺼낼 수 있는가 (Accessible) ──────────┤
 │  소유자·관리자 지정 · 접근 정책(RBAC/ABAC) · 개인정보 등급   │
 ├──────────── 관문 4: 믿을 수 있는가 (Trustworthy) ─────────┤
 │  데이터 계보(Lineage) · 품질 지표 · 최신성(SLA)             │
 └───────────────────────────┬────────────────────────────────┘
                             ▼
 [AI 활용]  피처 스토어 · 학습 데이터셋 · RAG 지식베이스
```

정제(클렌징)는 관문 4의 일부일 뿐이다. 앞의 세 관문이 막히면 데이터는 존재하지만 AI 관점에서는 없는 것과 같다.

### "더러운 데이터" vs "쓸 수 없는 데이터"

| 구분 | 더러운 데이터(Dirty) | 쓸 수 없는 데이터(Unusable) |
|---|---|---|
| 증상 | 결측·중복·오탈자·형식 오류 | 위치 불명·의미 불명·권한 불명 |
| 발견 시점 | 분석·학습 단계 | 데이터 탐색 단계(그 이전) |
| 원인 | 입력 통제·검증 규칙 부족 | 메타데이터·소유권·카탈로그 부재 |
| 주 대응 | 정제·표준화·검증 룰 | 카탈로그·용어집·계보·접근 정책 |
| 책임 주체 | 데이터 품질 담당 | 데이터 거버넌스 조직·데이터 오너 |
| 측정 지표 | 정확성·완전성·일관성 | 검색 성공률·메타데이터 충족률·접근 소요일 |
| AI 영향 | 모델 성능 저하 | 프로젝트 착수 지연·중단 |

### 메타데이터의 세 층위

| 유형 | 내용 | 예시 |
|---|---|---|
| 기술 메타데이터 | 스키마·타입·저장 위치·파티션 | `cust_tbl.birth_dt DATE` |
| 비즈니스 메타데이터 | 용어 정의·업무 규칙·소유 부서 | "활성 고객 = 최근 90일 거래" |
| 운영 메타데이터 | 적재 시각·갱신 주기·품질 점수·계보 | 매일 02시 적재, 완전성 99.2% |

세 층위 가운데 **비즈니스 메타데이터가 가장 자주 빠진다**. 컬럼명은 있으나 "이 값이 무엇을 기준으로 계산됐는지" 모르면, AI 학습에 쓰는 순간 잘못된 라벨이 된다.

### 관련 표준·기준
- **ISO/IEC 25012**: 데이터 품질 모델. 정확성·완전성 같은 **고유 특성**과 접근성·이식성 같은 **시스템 의존 특성**을 함께 정의한다. "쓸 수 없는 데이터"는 후자의 결함으로 설명할 수 있다.
- **ISO/IEC 11179**: 메타데이터 레지스트리(데이터 요소의 명명·정의·등록 규칙)
- **FAIR 원칙**: Findable·Accessible·Interoperable·Reusable — 연구 데이터 재사용성 원칙으로, AI-Ready 조건과 그대로 대응
- **DAMA-DMBOK**: 데이터 거버넌스를 중심으로 메타데이터·품질·보안 등 데이터 관리 지식영역을 정리한 지식체계
- **데이터기반행정법**: 공공기관 데이터 공동활용·제공 의무의 법적 근거

## 3. 기술사 출제 포인트

- AI-Ready 데이터의 정의와 4대 조건(발견·이해·접근·신뢰)
- 데이터 스웜프의 발생 원인과 방지 방안
- 기술·비즈니스·운영 메타데이터 구분과 관리
- 데이터 카탈로그와 비즈니스 용어집 구축
- 데이터 계보(Lineage) 추적과 영향도 분석
- ISO/IEC 25012 고유 품질과 시스템 의존 품질의 차이
- 데이터 오너·스튜어드 지정 등 거버넌스 역할 체계
- 접근 정책(RBAC/ABAC)과 개인정보 등급의 연동
- 데이터 준비도 측정 지표(메타데이터 충족률·접근 소요일)
- 레이크하우스·데이터 메시 환경의 메타데이터 통합

## 4. 연결 기출 토픽과 예상 변형

- **데이터 레이크·스웜프**: 139회 2교시에 **데이터 레이크와 데이터 스웜프**가 출제됐다. 이 뉴스의 "쓸 수 없는 데이터"는 스웜프의 증상을 AI 관점에서 다시 말한 것이라, 같은 문항이 "AI 활용 관점"으로 다시 나올 수 있다.
- **AI 학습용 데이터 품질관리**: 139회 3교시와 140회 2교시에 연속 출제됐다(140회는 특성·생애주기·원칙·범위·활동까지 요구). 다음 변형은 정제 중심 품질을 넘어 **메타데이터·접근성까지 포함한 준비도**를 묻는 방향이 자연스럽다.
- **데이터 자산화**: 139회 2교시 **데이터 가치평가 및 데이터 자산화**와 연결된다. 찾을 수 없는 데이터는 가치를 평가할 수도 없으므로, 카탈로그는 자산화의 선행 조건이다.
- **합성데이터**: 140회 3교시 **합성데이터 생성·품질 평가**도 "원천 데이터를 쓸 수 없을 때의 대안"이라는 맥락으로 묶을 수 있다.
- **예상 변형**
  - 1교시: "AI-Ready 데이터의 개념과 구성요건을 설명하시오"
  - 1교시: "데이터 계보(Data Lineage)의 개념과 활용 분야를 설명하시오"
  - 논술: "기업 AI 도입 실패 요인을 데이터 관점에서 분석하고, 메타데이터 관리 기반의 데이터 준비 체계를 제시하시오"

## 5. 답안 구성 예시

**단답형**(1교시, 1페이지)
- 정의: 내재 품질에 더해 발견·이해·접근·신뢰 가능성을 갖춰 AI에 즉시 투입 가능한 데이터
- 특징 3개: ① 메타데이터 기반 발견성 ② 정책 기반 접근성 ③ 계보·품질 지표 기반 신뢰성
- 구성도 키워드: 원천 → 카탈로그(찾기) → 메타데이터(이해) → 접근 정책(꺼내기) → 계보·품질(믿기) → AI 활용

**논술형(2~4교시) 목차**
1. 개요: AI 프로젝트 지연의 실제 원인 — 정제 이전 단계(탐색·접근)에서의 병목
2. 구성/비교: 4대 관문 구성도, 더러운 데이터 vs 쓸 수 없는 데이터 비교표, 메타데이터 3층위
3. 적용방안: 데이터 카탈로그·용어집 구축, 데이터 오너 지정, 계보 자동 수집, 접근 신청 워크플로 표준화
4. 고려사항: 메타데이터 최신성 유지 비용, 개인정보·영업비밀 등급 분류, 부서 간 소유권 갈등
5. 기술사 제언: 품질 점수만이 아니라 **메타데이터 충족률·접근 소요일**을 데이터 거버넌스 KPI로 관리하고, AI 과제 착수 전 데이터 준비도 진단을 의무화할 것
