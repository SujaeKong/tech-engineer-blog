## 1. 뉴스 요약

인공지능신문(11-18)은 **시마AI가 피지컬 AI 소프트웨어 '팔레트 3.0'을 공개하고, 단일 칩에서 여러 AI 모델을 동시에 실행**할 수 있게 했다고 보도했다. 로봇·자율주행차·드론 같은 피지컬 AI 기기는 카메라 인식, 위치 추정, 경로 계획, 음성·언어 이해 모델을 **한 기기 안에서 동시에, 정해진 시간 안에** 돌려야 한다. 칩을 기능마다 따로 두면 전력·비용·공간이 늘어나므로, 한 칩의 자원을 여러 모델이 나눠 쓰는 구조가 중요해졌다. 팔레트 3.0의 구체 구조는 제목 이상으로 확인되지 않으므로, 아래에서는 **단일 칩 멀티모델 실행 방식과 실시간 스케줄링**을 답안 재료로 정리한다.

## 2. 핵심 개념

### 정의
**단일 칩 멀티모델 실행**은 CPU·GPU·NPU·DSP 등이 한 칩에 통합된 **이기종 SoC**(System on Chip)에서 여러 AI 모델을 동시에 구동하면서, 각 모델의 **응답 시간 요구와 중요도에 맞게 연산·메모리 자원을 나눠 주는** 시스템 구성 방식이다. 이를 가능하게 하는 핵심이 **실시간 스케줄링**으로, 모든 작업이 마감 시간(Deadline) 안에 끝나도록 실행 순서와 자원 배분을 정하는 운영체제·런타임 기능이다.

### 구성도 ① — 이기종 SoC와 멀티모델 런타임

```
 ┌─────────────────────────── 이기종 SoC ───────────────────────────┐
 │  [CPU]  제어·OS·스케줄러·경량 후처리                               │
 │  [NPU]  신경망 추론(인식·분할 모델)                                │
 │  [GPU]  병렬 연산·대형 모델 일부                                   │
 │  [DSP/ISP]  영상 신호 처리·센서 전처리                             │
 │        └──────────── 공유 메모리(DRAM)·버스 ─────────────┘         │
 └──────────────────────────────────────────────────────────────────┘
                              ▲
 ┌──────────────────── 멀티모델 런타임 ─────────────────────┐
 │  모델 A: 장애물 인식   (주기 33ms, 안전 중요도 높음)       │
 │  모델 B: 위치 추정     (주기 50ms, 중요도 높음)            │
 │  모델 C: 경로 계획     (주기 100ms, 중요도 중간)           │
 │  모델 D: 음성·언어 이해 (비주기, 중요도 낮음)              │
 │  → 연산 장치 배치 · 실행 순서 · 메모리 예산 · 우선순위 결정 │
 └───────────────────────────────────────────────────────────┘
```

### 멀티모델 실행 방식 비교

| 방식 | 원리 | 장점 | 단점 | 적합 상황 |
|---|---|---|---|---|
| 시분할 | 가속기를 시간 단위로 번갈아 사용 | 구현 단순, 유연 | 전환 지연, 큰 모델이 작은 모델을 막음 | 모델 수가 적고 주기가 여유로울 때 |
| 공간 분할 | 연산 코어·MAC 배열을 모델별로 나눠 배정 | 간섭이 적고 지연 예측 쉬움 | 자원 낭비(유휴 코어) | 안전 중요 모델 격리 |
| 장치 분산 | 모델마다 CPU·GPU·NPU·DSP 중 적합한 장치에 배치 | 이기종 자원 활용 극대화 | 장치 간 데이터 이동 비용 | 모델 특성이 서로 다를 때 |
| 파이프라인 | 한 모델의 층을 여러 장치에 나눠 흐르게 함 | 처리량 증가 | 단계 균형 맞추기 어려움 | 연속 프레임 처리 |
| 공유 백본 | 여러 작업이 하나의 특징 추출부를 공유(멀티태스크) | 연산·메모리 대폭 절감 | 재학습 필요, 작업 간 성능 간섭 | 같은 입력을 쓰는 인식 작업들 |
| 동적 배치 | 요청을 모아 한 번에 처리 | 효율 향상 | 대기 시간 증가 | 처리량 중심 비실시간 작업 |

### 실시간 스케줄링 — RM vs EDF

| 구분 | RM(Rate Monotonic) | EDF(Earliest Deadline First) |
|---|---|---|
| 우선순위 결정 | 주기가 짧을수록 높게, 고정 | 마감이 가장 임박한 작업을 먼저, 동적 |
| 우선순위 유형 | 정적(고정 우선순위) | 동적 우선순위 |
| 이용률 한계(단일 처리기) | n(2^(1/n) − 1), n이 커지면 약 69% | 100%까지 스케줄 가능 |
| 구현 복잡도 | 낮음 | 상대적으로 높음 |
| 과부하 시 동작 | 낮은 우선순위 작업부터 마감 놓침(예측 가능) | 연쇄적으로 여러 작업이 마감을 놓칠 수 있음 |
| 분석·인증 | 응답 시간 분석이 성숙, 안전 인증에 유리 | 이론적 효율은 높지만 인증 사례 적음 |
| 적용 예 | 차량·항공 제어 등 안전 중요 시스템 | 이용률이 중요한 멀티미디어·일반 실시간 |

**이용률 계산**: 작업 i의 실행 시간 Ci, 주기 Ti라 하면 전체 이용률 U = Σ(Ci / Ti). 예를 들어 모델 A(10ms/33ms), B(10ms/50ms), C(20ms/100ms)라면 U ≈ 0.30 + 0.20 + 0.20 = 0.70이다. 작업 3개일 때 RM의 충분 조건 한계는 약 0.78이므로 RM으로도 스케줄 가능하다고 판정할 수 있다. 다만 AI 추론은 입력에 따라 실행 시간이 흔들리므로 **최악 실행 시간**(WCET)을 기준으로 계산해야 한다.

### 구성도 ② — 혼합 중요도 시스템의 간섭 배제

```
 [안전 중요 영역]  장애물 인식 · 비상 정지 판단
     │  전용 NPU 코어 분할 · 메모리 대역폭 예약 · 최우선 순위
     │  ── 간섭 배제(Freedom from Interference) 경계 ──
 [일반 영역]       경로 최적화 · 지도 갱신
     │  남는 자원에서 실행, 마감 놓치면 품질만 저하
     │
 [최선 노력 영역]  음성 대화 · 로그 업로드 · 언어 모델
        유휴 시간에만 실행, 필요 시 즉시 선점·중단
```

**혼합 중요도**(Mixed-Criticality) 시스템은 안전을 좌우하는 기능과 그렇지 않은 기능이 같은 하드웨어를 공유하는 구조다. 가장 큰 위험은 중요도 낮은 모델(예: 대형 언어 모델)이 메모리 대역폭을 많이 차지해 **안전 중요 모델의 지연이 늘어나는 간섭**이다. 그래서 연산 코어뿐 아니라 **메모리 대역폭·캐시·버스까지 분할하거나 예약**하는 설계가 필요하다.

### 설계 시 고려사항
- **메모리 대역폭 경합**: 여러 모델이 같은 DRAM을 쓰면 연산 자원이 남아도 메모리에서 병목이 생긴다. 모델별 대역폭 상한과 온칩 메모리 배분이 필요하다.
- **실행 시간 변동**: 입력 장면이 복잡해지면 후처리 시간이 늘어난다. 최악 실행 시간 측정과 여유분 확보가 필요하다.
- **열·전력 제약**: 동시 실행으로 칩 온도가 오르면 클럭이 낮아져 전체 일정이 밀린다. 열 여유를 스케줄 분석에 넣는다.
- **모델 교체**: 기능 추가로 모델이 바뀌면 이용률 분석을 다시 해야 한다. 모델 배포 파이프라인에 스케줄 가능성 검증을 넣는다.

### 관련 표준
- **ISO 26262**: 자동차 기능 안전 — ASIL 분해와 간섭 배제 요구
- **IEC 61508**: 전기·전자·프로그래머블 안전 시스템의 기능 안전
- **ISO 21448**(SOTIF): 의도된 기능의 안전 — 인식 성능 한계에 따른 위험
- **POSIX 실시간 확장**: 고정 우선순위 스케줄링 정책 등 실시간 운영체제 인터페이스

## 4. 연결 기출 토픽과 예상 변형

- **NPU**: 140회 1교시에 **NPU**가 출제됐다. NPU 내부 구조를 묻고 나면, 여러 모델이 NPU를 나눠 쓰는 방식으로 확장되는 변형이 자연스럽다.
- **피지컬 AI**: 140회 1교시 **Physical AI와 생성형 AI 비교**가 출제됐다. 피지컬 AI가 생성형 AI와 다른 핵심 요구가 실시간성과 안전이라는 점을 이 글의 스케줄링 내용으로 뒷받침할 수 있다.
- **메모리 벽**: 140회 3교시 **메모리 벽·CXL 3.0**이 출제됐다. 멀티모델 실행의 메모리 대역폭 경합은 칩 수준의 메모리 벽 문제다.
- **운영체제**: 140회 1교시 **좀비 프로세스**처럼 운영체제 기본 개념이 계속 출제되고 있다. 실시간 스케줄링(RM·EDF)은 운영체제 영역의 빈출 토픽이다.
- **예상 변형**
  - 1교시: "RM(Rate Monotonic)과 EDF(Earliest Deadline First) 스케줄링을 비교하시오"
  - 1교시: "혼합 중요도(Mixed-Criticality) 시스템을 설명하시오"
  - 논술: "피지컬 AI 기기에서 단일 SoC로 여러 AI 모델을 실시간 구동하기 위한 자원 관리 방안을 제시하시오"

## 5. 답안 구성 예시

**단답형**(1교시, 1페이지)
- 정의: 주기가 짧은 작업일수록 높은 고정 우선순위를 주는 정적 실시간 스케줄링(RM)과, 마감이 임박한 작업을 먼저 실행하는 동적 스케줄링(EDF)
- 특징 3개: ① RM은 이용률 한계 약 69%, 예측 가능 ② EDF는 이용률 100%까지 가능, 과부하 시 연쇄 실패 ③ 둘 다 WCET 기반 분석 필요
- 구성도 키워드: 작업(Ci, Ti) → 이용률 U = ΣCi/Ti → 스케줄 가능성 판정 → 우선순위 할당

**논술형(2~4교시) 목차**
1. 개요: 피지컬 AI 확산과 단일 칩 멀티모델 실행 수요
2. 구성/비교: 이기종 SoC 구성도, 실행 방식 비교표, RM vs EDF 비교표, 혼합 중요도 구성도
3. 적용방안: 중요도별 영역 분리, 안전 모델 공간 분할, 메모리 대역폭 예약, WCET 기반 이용률 분석, 공유 백본으로 연산 절감
4. 고려사항: 실행 시간 변동, 메모리 경합, 열 제약, 모델 교체 시 재검증, 기능 안전 인증
5. 기술사 제언: 멀티모델 성능을 평균 처리량이 아니라 **안전 중요 모델의 최악 응답 시간**으로 평가하고, 모델 배포 때마다 스케줄 가능성 검증을 자동으로 수행하는 절차를 둘 것
