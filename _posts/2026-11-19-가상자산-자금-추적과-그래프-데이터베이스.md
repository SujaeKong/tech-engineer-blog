## 1. 뉴스 요약

데일리팝(11-18)은 **두나무가 거래소 지갑 식별과 자금 추적 등의 기술 연구를 이어가며, 그 결과를 업비트 데이터랩에 적용**한다고 보도했다. 블록체인 거래는 누구나 볼 수 있는 공개 원장에 남지만, 주소는 실명이 아닌 무작위 문자열이고 자금은 수십 단계를 거쳐 쪼개지고 합쳐진다. 그래서 자금 추적은 결국 "**수억 건의 거래 관계 속에서 경로를 찾는 문제**"가 되고, 여기에 관계 탐색에 특화된 **그래프 데이터 모델**이 쓰인다. 두나무 기술의 구체 구조는 제목 이상으로 확인되지 않으므로, 아래에서는 **블록체인 자금 추적의 그래프 모델링과 그래프 DB**를 답안 재료로 정리한다.

## 2. 핵심 개념

### 정의
**그래프 데이터베이스**는 데이터를 **노드**(Node, 개체)와 **관계**(Edge, 연결), 그리고 각각에 붙는 **속성**(Property)으로 저장하고, 관계를 따라가는 탐색을 핵심 연산으로 최적화한 DBMS다. **블록체인 자금 추적**은 공개 원장의 거래를 주소–거래–주소의 그래프로 모델링한 뒤, **주소 클러스터링으로 같은 소유자를 묶고 경로 탐색으로 자금 흐름을 따라가** 범죄 수익·제재 대상과의 연관성을 찾는 분석이다.

### 블록체인 거래 모델 비교

| 구분 | UTXO 모델 | 계정 모델 |
|---|---|---|
| 대표 체인 | 비트코인 | 이더리움 |
| 잔액 개념 | 사용되지 않은 거래 출력(UTXO)의 합 | 계정별 잔액 상태 |
| 거래 구조 | 여러 입력 → 여러 출력 | 한 계정 → 한 계정(+스마트 계약 호출) |
| 잔돈 처리 | 잔돈 주소로 되돌려 받음 | 잔액에서 차감 |
| 그래프 모델링 | 거래를 노드로 두는 이분 그래프가 자연스러움 | 계정 간 송금 관계로 직접 연결 |
| 추적 난점 | 잔돈 주소 식별, 다중 입력·출력 | 스마트 계약·토큰 내부 이동, 체인 브리지 |

### 구성도 ① — 자금 추적 그래프 데이터 모델

```
 (주소 A) ──[송금 {금액, 시각, 거래ID}]──▶ (주소 B) ──[송금]──▶ (주소 C)
    │                                         │
    │[소속]                                   │[소속]
    ▼                                         ▼
 (엔터티: 해킹 사건 지갑)                 (엔터티: 믹서 서비스)
                                              │
                                    ┌─────────┴─────────┐
                                    ▼                   ▼
                              (주소 D) ──▶ … ──▶ (거래소 입금 주소)
                                                        │[소속]
                                                        ▼
                                              (엔터티: 국내 거래소 X)

 노드 유형: 주소 · 거래 · 엔터티(거래소·믹서·제재 대상·서비스)
 관계 유형: 송금 · 입력/출력 · 소속(클러스터) · 동일 소유 추정
 속성: 금액 · 시각 · 체인 · 위험 등급 · 근거(휴리스틱 종류)
```

### 주소 클러스터링 휴리스틱
- **공동 입력 소유**: UTXO 거래에서 여러 입력 주소를 함께 쓰려면 모든 개인키가 필요하므로, 같은 거래의 입력 주소들은 같은 소유자로 추정한다. 가장 널리 쓰이는 휴리스틱이다.
- **잔돈 주소 추정**: 출력 중 새로 생성된 주소, 금액 자릿수 패턴 등으로 잔돈 주소를 골라 송신자와 묶는다.
- **거래소 입금 패턴**: 거래소는 이용자별 입금 주소에서 핫월렛으로 자금을 모으므로, 이 집금 패턴으로 거래소 주소군을 식별한다.
- **한계**: 여러 사람이 입력을 함께 내는 **코인조인**은 공동 입력 소유 가정을 깨뜨린다. 휴리스틱마다 **오탐 위험**이 있어, 관계에 추정 근거와 신뢰도를 속성으로 함께 저장해야 한다.

### 그래프 질의 패턴

| 질의 패턴 | 내용 | 자금 추적 활용 |
|---|---|---|
| k-홉 탐색 | 시작 노드에서 k단계 이내의 연결 노드 | 해킹 지갑에서 3단계 안의 거래소 입금 주소 찾기 |
| 최단 경로 | 두 노드 사이 최소 단계 경로 | 의심 주소와 제재 대상 사이 연관성 |
| 시간 제약 경로 | 시각이 증가하는 순서로만 이어지는 경로 | 실제 자금 이동 순서에 맞는 흐름만 추적 |
| 팬아웃·팬인 패턴 | 하나에서 다수로 분산, 다수에서 하나로 집결 | 쪼개기(분산 세탁)·집금 탐지 |
| 필 체인(Peel Chain) | 큰 금액에서 조금씩 떼어 내며 길게 이어지는 경로 | 세탁 패턴 식별 |
| 커뮤니티 탐지 | 촘촘히 연결된 노드 집단 | 조직적 세탁 네트워크 식별 |
| 위험 전파 | 위험 노드에서 연결 강도에 따라 점수 확산 | 주소별 위험 등급 산정 |

### 관계형 DB vs 그래프 DB

| 구분 | 관계형 DB | 그래프 DB |
|---|---|---|
| 데이터 모델 | 테이블·행·외래키 | 노드·관계·속성 |
| 관계 탐색 | 조인(JOIN) 반복, 단계가 늘수록 비용 급증 | 인접 노드를 바로 따라감(인덱스 없는 인접성) |
| 스키마 | 사전 정의, 변경 비용 큼 | 유연, 새 관계 유형 추가 쉬움 |
| 질의 언어 | SQL | GQL·Cypher 등 패턴 매칭 언어 |
| 강점 | 집계·트랜잭션·정형 보고 | 다단계 연결·경로·패턴 탐색 |
| 약점 | 깊은 재귀 관계 질의 | 대규모 전체 집계, 분산 처리의 어려움 |
| 자금 추적 역할 | 거래 원장 보관·집계·감사 보고 | 경로 추적·클러스터·패턴 분석 |

실무에서는 하나를 고르기보다 **원장과 집계는 관계형·분석형 저장소에, 관계 분석은 그래프 DB에** 두는 혼합 구성이 일반적이다.

### 구성도 ② — 자금 추적 분석 파이프라인

```
 [블록체인 노드]  다중 체인 블록·거래 수집
      │
      ▼
 [정규화·적재]  체인별 형식 통일 → 원장 저장소(관계형·컬럼형)
      │
      ▼
 [그래프 구축]  주소·거래·관계 생성 → 클러스터링 휴리스틱 적용
      │
      ▼
 [라벨링]  거래소·믹서·제재 대상·사건 지갑 라벨 결합
      │
      ▼
 [분석]  경로 탐색 · 패턴 탐지 · 위험 점수 산정
      │
      ▼
 [활용]  입출금 위험 심사 · 의심거래 보고 · 수사 지원 · 트래블 룰 연계
```

### 관련 표준·법령
- **ISO/IEC 39075 GQL**: 속성 그래프 질의 언어 국제표준(2024)
- **ISO/IEC 9075-16 SQL/PGQ**: SQL 안에서 속성 그래프를 질의하는 확장(2023)
- **특정금융정보법**: 가상자산사업자 신고·의심거래 보고 의무, 트래블 룰(일정 금액 이상 이전 시 송수신인 정보 제공)
- **가상자산이용자보호법**: 이용자 자산 보호, 불공정거래 규제
- **FATF 권고**: 가상자산사업자 규제와 트래블 룰의 국제 기준

## 4. 연결 기출 토픽과 예상 변형

- **블록체인**: 블로그 통합 기출 분석(`exam_trend_integrated.json`) 기준 **블록체인은 기출 22회**로 최다 빈출 키워드 중 하나다. 블록체인 문항에서 "투명성"을 쓸 때, 공개 원장이 곧 추적 가능성으로 이어지는 구조를 함께 쓰면 차별화된다.
- **분산 DB**: 139회 1교시에 **분산 데이터베이스의 투명성**이 출제됐다. 데이터베이스 영역의 데이터 모델 비교 문항으로 그래프 DB가 이어서 나올 수 있다.
- **이상치·클러스터링**: 139회 4교시 **클러스터링과 이상치 탐지**가 출제됐다. 주소 클러스터링과 세탁 패턴 탐지는 이 문항의 응용 사례다.
- **예상 변형**
  - 1교시: "그래프 데이터베이스와 관계형 데이터베이스를 비교하시오"
  - 1교시: "GQL(Graph Query Language)을 설명하시오"
  - 논술: "가상자산 자금세탁 방지를 위한 그래프 기반 자금 추적 시스템 구축 방안을 제시하시오"

## 5. 답안 구성 예시

**단답형**(1교시, 1페이지)
- 정의: 데이터를 노드·관계·속성으로 저장하고 관계 탐색을 핵심 연산으로 최적화한 DBMS
- 특징 3개: ① 인접 노드를 바로 따라가는 다단계 탐색 ② 유연한 스키마 ③ GQL·Cypher 패턴 매칭 질의
- 구성도 키워드: (주소)–[송금]→(주소), (주소)–[소속]→(엔터티) / k-홉·최단 경로·시간 제약 경로

**논술형(2~4교시) 목차**
1. 개요: 공개 원장과 익명 주소, 그래프 기반 자금 추적의 필요성
2. 구성/비교: 그래프 데이터 모델, UTXO vs 계정 모델 비교표, 질의 패턴표, RDB vs 그래프 DB 비교표
3. 적용방안: 원장·그래프 혼합 저장 구조, 휴리스틱 근거·신뢰도 속성화, 시간 제약 경로 탐색, 라벨 데이터 공유, 트래블 룰 연계
4. 고려사항: 휴리스틱 오탐에 따른 정상 이용자 피해, 코인조인·체인 브리지, 데이터 규모와 분산 처리, 개인정보 보호
5. 기술사 제언: 추적 결과를 **확정 사실이 아닌 근거와 신뢰도가 붙은 추정**으로 관리하고, 자동 차단보다 사람 검토를 거치는 단계형 대응으로 오탐 피해를 줄일 것
