## 1. 뉴스 요약

인포스탁데일리(10-28)는 **유엔젤이 5G 코어와 MEC(Multi-access Edge Computing) 기술로 AI 인프라 시장을 정조준**한다고 보도했다. AI 추론을 사용자 가까운 곳에서 처리하려면, 이동통신망이 데이터를 **중앙 데이터센터까지 보내지 않고 가까운 엣지 서버로 바로 넘겨주는** 구조가 필요하다. 그 열쇠가 5G 코어의 구조와 MEC 연동 방식이다. 회사의 제품 구성은 제목 이상으로 확인되지 않으므로, 이 글은 기사를 계기로 **5G 코어 SBA와 MEC 연동**을 깊게 다루는 토픽 심화 글이다.

## 2. 핵심 개념

### 정의
**5G 코어**(5GC)는 이동통신망의 두뇌로, 가입자 인증·이동성·세션·정책을 관리하는 네트워크 기능(NF)들이 **표준 API로 서로 서비스를 주고받는 서비스 기반 아키텍처**(SBA, Service Based Architecture)로 설계됐다. **MEC**는 기지국 가까이에 컴퓨팅 자원을 두고 애플리케이션을 실행해 **지연을 줄이고 백홀 트래픽을 절감**하는 기술이며, 5G 코어의 사용자 평면 기능(UPF)을 엣지에 분산 배치해 트래픽을 그곳으로 빼내는 방식으로 연동된다.

### 구성도 — 5G 코어 SBA와 MEC 연동

```
                 ┌──────────── 제어 평면 (중앙) ─────────────┐
                 │  AMF   SMF   PCF   UDM   AUSF   NRF   NSSF  NEF │
                 │   └────┴─────┴── 서비스 기반 인터페이스(HTTP/2 API) ─┘
                 └──────┬───────────────┬───────────────────────────┘
                        │ N2            │ N4 (SMF가 UPF 제어)
   단말 ── 기지국(gNB) ─┤               ├──────────────┐
                        │ N3            ▼              ▼
                        └──────▶ [엣지 UPF] ──N6──▶ [MEC 서버: AI 추론·영상 분석]
                                     │ (로컬 브레이크아웃)
                                     └──N9──▶ [중앙 UPF] ──N6──▶ 인터넷·중앙 클라우드

   NEF: MEC 애플리케이션이 코어에 트래픽 경로·QoS를 요청하는 외부 개방 창구
```

같은 사용자의 트래픽 중 **AI 추론 요청은 엣지 UPF에서 바로 MEC 서버로**, 일반 인터넷 트래픽은 중앙 UPF로 보내는 식으로 경로를 나눌 수 있다. 이 분기를 결정하는 것이 SMF이고, 정책은 PCF가 정한다.

### 주요 네트워크 기능(NF)

| NF | 역할 | 4G 대응 |
|---|---|---|
| AMF | 접속·이동성 관리 | MME(일부) |
| SMF | 세션 관리, UPF 선택·제어 | MME·S/P-GW 제어부 |
| UPF | 사용자 데이터 전달·라우팅 | S/P-GW 사용자부 |
| PCF | 정책·과금 규칙 | PCRF |
| UDM / AUSF | 가입자 정보 / 인증 | HSS |
| NRF | NF 등록·검색(서비스 디스커버리) | 없음 |
| NSSF | 네트워크 슬라이스 선택 | 없음 |
| NEF | 외부 애플리케이션에 망 기능 개방 | SCEF |

### 4G EPC vs 5G 코어

| 구분 | 4G EPC | 5G 코어(5GC) |
|---|---|---|
| 구조 | 장비 간 점대점 인터페이스 | 서비스 기반 아키텍처(SBA) |
| 인터페이스 | Diameter·GTP-C 등 전용 프로토콜 | HTTP/2 기반 REST API |
| 제어·사용자 평면 | 후기 표준에서 분리(CUPS) | 처음부터 완전 분리 |
| 구현 형태 | 전용 장비 중심 | 가상화·클라우드 네이티브(컨테이너) |
| 슬라이싱 | 제한적 | 네트워크 슬라이싱 기본 지원 |
| 엣지 연동 | 제한적 | UPF 분산 배치로 MEC 연동 용이 |
| 외부 개방 | SCEF | NEF로 API 개방 |

### MEC 트래픽 분기 방식
- **UL CL**(Uplink Classifier): 하나의 세션 안에서 목적지 주소에 따라 트래픽을 엣지 UPF와 중앙 UPF로 나눈다.
- **멀티 홈**(IPv6 Multi-homing): 단말이 두 개의 IP 주소를 받아 경로를 나눈다.
- **로컬 데이터 네트워크**(LADN): 특정 지역에서만 접속 가능한 데이터 네트워크를 지정한다(공장·경기장 등).

### 관련 표준
- **3GPP Rel-15/16/17**: 5G 코어 SBA 정의(Rel-15), 산업용·엣지 기능 확장(Rel-16·17)
- **ETSI MEC**: MEC 참조 구조와 애플리케이션 API 표준
- **3GPP TS 23.501 / 23.548**: 5G 시스템 구조 / 엣지 컴퓨팅 지원

## 4. 연결 기출 토픽과 예상 변형

- **5G**: 블로그 통합 기출 분석(`exam_trend_integrated.json`) 기준 **5G는 기출 13회**로 네트워크 최빈출 키워드다. 5G 코어 구조와 MEC는 5G 문항의 단골 하위 주제다.
- **엣지 컴퓨팅**: 같은 분석 기준 엣지 컴퓨팅은 기출 9회이며, 139회 1교시에 **엣지 vs 클라우드 컴퓨팅**이 출제됐다. MEC는 통신망 안에 들어간 엣지 컴퓨팅이라는 점에서 바로 연결된다.
- **QoS**: 140회 2교시 **FIFO vs WFQ**처럼 트래픽 처리 기본기 문항이 꾸준하다. PCF 정책과 QoS 흐름 제어는 같은 맥락이다.
- **클라우드 네이티브**: 140회 2교시 **서버리스**, 3교시 **클라우드 네이티브 재해복구**가 출제됐다. 5G 코어 NF의 컨테이너화는 클라우드 네이티브의 통신 분야 사례다.
- **예상 변형**
  - 1교시: "5G 코어의 서비스 기반 아키텍처(SBA)를 설명하시오"
  - 1교시: "MEC(Multi-access Edge Computing)의 구조와 5G 코어 연동 방식을 설명하시오"
  - 논술: "AI 서비스 확산에 대응한 5G 코어·MEC 기반 엣지 인프라 구축 방안을 제시하시오"

## 5. 답안 구성 예시

**단답형**(1교시, 1페이지)
- 정의: 네트워크 기능들이 표준 API로 서비스를 주고받는 5G 코어 구조(SBA), MEC는 UPF 분산으로 엣지 연동
- 특징 3개: ① HTTP/2 기반 서비스 인터페이스 ② 제어·사용자 평면 완전 분리 ③ UPF 분산 배치로 로컬 브레이크아웃
- 구성도 키워드: 단말 → gNB → 엣지 UPF → MEC 서버 / 중앙 UPF → 인터넷 (SMF·PCF 제어, NEF 개방)

**논술형(2~4교시) 목차**
1. 개요: AI 추론의 저지연 요구와 이동통신망 엣지의 역할
2. 구성/비교: SBA·MEC 연동 구성도, NF 역할표, 4G EPC vs 5GC 비교표
3. 적용방안: 엣지 UPF 배치 위치 선정, UL CL 기반 트래픽 분기, NEF API로 서비스 연동, 슬라이스별 QoS
4. 고려사항: 엣지 거점 수와 비용, 이동 시 세션 연속성, API 개방에 따른 보안, 다수 사업자 간 연동
5. 기술사 제언: MEC를 망 사업자 내부 기능이 아니라 **NEF로 개방된 플랫폼**으로 설계하고, AI 서비스 지연 목표에 맞춰 엣지 거점을 단계적으로 늘릴 것
