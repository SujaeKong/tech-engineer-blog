## 1. 뉴스 요약

누리일보·제주팟닷컴(11-25)은 **JDC(제주국제자유도시개발센터)와 공무원연금공단이 'AI 감사·윤리헌장'을 공동 선포**했다고 보도했다. 공공기관 감사 조직이 AI를 감사 업무에 쓰면서, 그 과정에서 지켜야 할 원칙을 먼저 세운 것이다. 감사는 오랫동안 **일부 표본을 뽑아 들여다보는 방식**이었지만, 업무가 전산화되고 데이터가 쌓이면서 **전체 거래를 상시 분석하는 방식**으로 바뀌고 있다. 헌장의 구체 조항은 제목 이상으로 확인되지 않으므로, 아래에서는 **AI 기반 내부감사와 연속 감사의 구조, 윤리 원칙**을 정리한다.

## 2. 핵심 개념

### 정의
**AI 기반 내부감사**는 조직의 거래·업무 기록 전체를 데이터 분석과 AI로 점검해 **이상 징후·통제 위반·부정 위험을 찾아내고, 감사 자원을 위험이 큰 곳에 집중**하는 감사 방식이다. 그 중심 개념인 **연속 감사**(Continuous Auditing)는 정기 감사 시점을 기다리지 않고 **자동화된 분석을 짧은 주기로 반복해 통제 위반을 거의 실시간으로 발견**하는 것이다. 감사의 목적은 그대로지만, **표본에서 전수로, 사후에서 상시로** 바뀐다는 점이 핵심 차이다.

### 전통 감사 vs AI 기반 연속 감사

| 구분 | 전통 감사 | AI 기반 연속 감사 |
|---|---|---|
| 대상 범위 | 표본 추출 | 전체 거래 전수 분석 |
| 주기 | 연간·분기 정기 감사 | 일·주 단위 상시 분석 |
| 발견 시점 | 사건 발생 후 수개월 | 발생 직후 |
| 감사 계획 | 순환·관행 중심 | 위험 점수 기반 우선순위 |
| 분석 방법 | 문서 검토·면담 | 규칙 기반 검사 + 이상 탐지 + 프로세스 마이닝 |
| 감사인 역할 | 자료 수집·대사 | 이상 징후 검증·판단·개선 권고 |
| 한계 | 표본 밖 위험 누락 | 데이터 품질 의존, 오탐 처리 부담 |

### 3선 모델과 연속 감사·연속 모니터링

```
 [이사회·감사위원회]  감독
        │
 ┌──────┼────────────────────────────────────────┐
 │ [1선] 업무 부서      업무 수행·자체 통제          │
 │        └ 연속 모니터링(CM): 경영진이 통제 운영 상태를 상시 확인
 │ [2선] 리스크·준법    위험관리 체계·정책·점검       │
 │ [3선] 내부감사       독립적 검증·보증              │
 │        └ 연속 감사(CA): 감사인이 독립적으로 상시 분석
 └─────────────────────────────────────────────────┘
        │
 [외부 감사·감독기관]
```

**연속 모니터링**은 1선·2선이 자기 통제를 상시 점검하는 **경영 활동**이고, **연속 감사**는 3선 감사인이 독립적으로 수행하는 **보증 활동**이다. 같은 분석 도구를 써도 주체와 목적이 다르므로 답안에서 구분해 써야 한다. 연속 모니터링이 잘 갖춰질수록 감사는 모니터링 체계 자체가 제대로 작동하는지 검증하는 데 집중할 수 있다.

### 구성도 ① — AI 연속 감사 체계

```
 [데이터 원천]  회계·구매·급여·계약·출장 · 접근 로그 · 결재 이력
      │  읽기 전용 추출(원본 무결성 보장)
      ▼
 [감사 데이터 저장소]  표준화 · 이력 보관 · 접근 통제
      │
      ▼
 [분석]
   ├ 규칙 기반 검사: 중복 지급 · 결재 권한 위반 · 쪼개기 계약 · 휴일 처리
   ├ 이상 탐지: 평소 패턴과 다른 거래 · 금액 분포 이상(벤포드 법칙)
   ├ 프로세스 마이닝: 실제 업무 흐름과 규정 흐름 비교
   └ 텍스트 분석: 계약서·결재 의견의 위험 표현
      │
      ▼
 [위험 점수화]  부서·거래처·개인별 위험 순위
      │
      ▼
 [감사인 검증]  오탐 제거 · 사실 확인 · 증거 확보
      │
      ▼
 [조치·개선]  통제 개선 권고 · 규칙 갱신 → 분석으로 환류
```

### 주요 분석 기법

| 기법 | 원리 | 감사 활용 | 주의점 |
|---|---|---|---|
| 규칙 기반 검사 | 정해진 조건 위반 탐지 | 중복 지급, 권한 초과 결재 | 알려진 유형만 탐지 |
| 이상 탐지 | 정상 패턴에서 벗어난 거래 탐지 | 비정상 금액·시간·거래처 | 오탐 많음, 설명 필요 |
| 벤포드 법칙 | 자연 발생 수치의 첫 자릿수 분포 비교 | 조작된 금액 의심 | 적용 가능한 데이터 한정 |
| 프로세스 마이닝 | 이벤트 로그로 실제 업무 흐름 복원 | 결재 생략·순서 위반 | 로그 품질 필요 |
| 네트워크 분석 | 거래 관계 그래프 분석 | 담합·특수관계 거래 | 관계 데이터 확보 |
| 텍스트 분석·LLM | 문서 내용 분류·요약 | 계약 조건 위험, 증빙 검토 | 환각, 근거 확인 필수 |

### 프로세스 마이닝
프로세스 마이닝은 시스템에 남은 **이벤트 로그**(사례 ID·활동·시각)로 업무가 실제로 어떻게 흘러갔는지 복원한다. 세 가지 활용이 있다.
- **발견**(Discovery): 로그에서 실제 프로세스 모델을 도출
- **적합성 검사**(Conformance): 규정상 흐름과 실제 흐름의 차이 탐지 — 예) 구매 요청 없이 발주, 승인 전 지급
- **개선**(Enhancement): 병목·재작업 구간을 찾아 프로세스 개선

감사 관점에서는 적합성 검사가 가장 직접적으로 쓰인다.

### 구성도 ② — AI 감사 윤리 원칙

```
 [적법성]   감사 권한 범위 안에서만 데이터 수집·분석
     │
 [비례성]   목적에 필요한 최소 데이터, 개인 감시로 확대 금지
     │
 [사람의 판단]  AI 결과는 감사 단서일 뿐, 처분은 감사인이 사실 확인 후 결정
     │
 [설명 가능성]  지적 사항에는 AI 점수가 아닌 확인된 사실·근거를 제시
     │
 [보안·기밀]  감사 데이터 접근 통제, 외부 AI 서비스 입력 제한
     │
 [검증·책임]  분석 모델의 정확도·편향 점검, 오류 시 책임 소재 명확화
```

AI가 위험하다고 표시한 직원이 실제로는 문제가 없을 수 있다. **AI 점수만으로 징계·처분을 하지 않는다**는 원칙이 감사 윤리의 출발점이다.

### 도입 시 고려사항
- **데이터 품질**: 시스템마다 코드·형식이 다르면 분석 결과를 믿기 어렵다. 감사용 데이터 표준화가 먼저다.
- **오탐 관리**: 경보가 너무 많으면 감사인이 모두 확인할 수 없다. 위험 점수로 우선순위를 정하고 규칙을 계속 조정한다.
- **독립성**: 1선 업무 시스템에 감사 분석을 직접 심으면 감사의 독립성이 흐려질 수 있다. 읽기 전용 접근과 별도 저장소를 둔다.
- **역량**: 감사인에게 데이터 분석 역량과 IT 이해가 함께 필요하다.

### 관련 기준
- **IIA 3선 모델**: 운영·리스크관리·내부감사의 역할 구분
- **IIA 글로벌 내부감사 기준**: 내부감사 직무 수행 원칙
- **COBIT**: IT 거버넌스·통제 프레임워크
- **공공감사에 관한 법률**: 공공기관 자체감사기구의 운영 근거
- **인공지능기본법**: AI 활용 시 투명성·사람의 관리·감독 원칙

- AI 기반 내부감사와 연속 감사의 정의
- 전통 표본 감사와 전수·상시 분석 비교
- 3선 모델과 연속 감사(CA)·연속 모니터링(CM)의 구분
- AI 연속 감사 체계(원천→저장소→분석→위험 점수→검증→개선)
- 규칙 기반 검사·이상 탐지·벤포드 법칙·네트워크 분석

- AI 감사 윤리(적법성·비례성·사람의 판단·설명 가능성)
- 감사 독립성과 데이터 무결성(읽기 전용 추출)
- 오탐 관리와 위험 기반 감사 계획

## 4. 연결 기출 토픽과 예상 변형

- **AI 기반 BPR**: 140회 1교시에 **AI 기반 BPR**이 출제됐다. 프로세스 마이닝은 현행 업무 흐름을 데이터로 복원하는 BPR의 핵심 도구이기도 하다.
- **표본추출·통계**: 140회 4교시에 **표본추출 방법**, 139회 1교시에 **대수의 법칙과 중심극한정리**가 출제됐다. 표본 감사의 한계와 전수 분석으로의 전환을 비교하는 답안 재료가 된다.
- **이상치 탐지**: 139회 4교시 **클러스터링과 이상치**, 140회 4교시 **시계열 이상치 탐지**가 출제됐다. 감사 이상 탐지의 기반 기법이다.
- **컴플라이언스**: 140회 4교시 **정보보호 컴플라이언스**가 출제됐다. 연속 모니터링은 준법 상태를 상시 확인하는 수단이다.
- **예상 변형**
  - 1교시: "연속 감사(Continuous Auditing)와 연속 모니터링(Continuous Monitoring)을 비교하시오"
  - 1교시: "프로세스 마이닝(Process Mining)을 설명하시오"
  - 논술: "공공기관 내부감사에 AI를 도입하기 위한 체계와 윤리적 고려사항을 제시하시오"

## 5. 답안 구성 예시

**단답형**(1교시, 1페이지)
- 정의: 자동화된 분석을 짧은 주기로 반복해 전체 거래의 통제 위반을 거의 실시간으로 발견하는 감사 방식(연속 감사)
- 특징 3개: ① 표본이 아닌 전수 분석 ② 위험 점수 기반 감사 자원 배분 ③ 3선 감사인의 독립적 보증 활동(1·2선의 연속 모니터링과 구분)
- 구성도 키워드: 데이터 원천 → 감사 저장소(읽기 전용) → 규칙·이상 탐지·프로세스 마이닝 → 위험 점수 → 감사인 검증 → 개선

**논술형(2~4교시) 목차**
1. 개요: 감사 업무의 AI 도입과 감사·윤리헌장
2. 구성/비교: 전통 vs 연속 감사 비교표, 3선 모델도, AI 연속 감사 구성도, 분석 기법표, 윤리 원칙도
3. 적용방안: 감사 데이터 표준화와 읽기 전용 저장소, 위험 점수 기반 감사 계획, 프로세스 마이닝 적합성 검사, LLM 증빙 검토 보조, 연속 모니터링과의 역할 분담
4. 고려사항: 데이터 품질, 오탐 부담, 감사 독립성, 개인 감시 우려, 감사인 역량
5. 기술사 제언: AI 감사의 성과를 지적 건수가 아니라 **위험 발견까지 걸린 시간과 통제 개선 이행률**로 측정하고, AI 결과를 처분 근거로 쓰지 않는 원칙을 헌장과 절차서에 명문화할 것
