## 1. 뉴스 요약

문화일보·광흥타임즈·비욘드포스트 등(10-20)은 **안양시가 중앙시장에 '피지컬 AI 순찰로봇'을 투입해 전통시장 생활안전을 강화**한다고 보도했다. 사람이 상시 순찰하기 어려운 시장 공간을 로봇이 돌며 안전을 지키겠다는 취지의 지자체 실증이다. 로봇의 구체 사양이나 탐지 기능은 보도 제목 이상으로 확인되지 않으므로, 아래에서는 공공 공간 순찰로봇이 일반적으로 갖추는 **시스템 구조와 엣지-클라우드 처리 분담**을 답안 재료로 정리한다.

## 2. 핵심 개념

### 정의
**순찰로봇 시스템**은 이동 로봇이 센서로 주변을 **인지**하고, 위험 여부를 **판단**해, 주행·경보를 **제어**하는 피지컬 AI 시스템이며, 실시간성이 필요한 처리는 로봇 내부(엣지)에서, 집계·학습·관제는 서버(클라우드)에서 수행하도록 **처리 위치를 계층적으로 분담**하는 것이 설계의 중심이다.

### 구성도 — 순찰로봇 계층 구조

```
 ┌─────────────────── 클라우드 / 관제센터 ───────────────────┐
 │ 관제 대시보드 · 이벤트 이력 · 모델 재학습 · 순찰 경로 계획 │
 │ OTA 업데이트 · 다수 로봇 통합 관리(Fleet Management)       │
 └──────────────▲────────────────────────────┬────────────────┘
       이벤트·요약 영상 (수 초~분 허용)        │ 모델·경로·정책 배포
 ┌──────────────┴────────────────────────────▼────────────────┐
 │                    로봇 온보드(엣지)                        │
 │ [인지]  카메라 · LiDAR · 열화상 · 마이크 → 객체·이상 탐지    │
 │ [판단]  위험 분류 · 경보 여부 결정 · 경로 재계획              │
 │ [제어]  주행 제어 · 장애물 회피 · 비상정지 (ms 단위 루프)    │
 │ [안전]  하드웨어 비상정지 · 속도 제한 · 통신 두절 시 정지/복귀│
 └────────────────────────────────────────────────────────────┘
        미들웨어: ROS 2(DDS 기반 발행/구독, QoS 정책)
```

### 엣지 처리 vs 클라우드 처리

| 구분 | 로봇 온보드(엣지) | 클라우드·관제 서버 |
|---|---|---|
| 주 기능 | 주행 제어·장애물 회피·1차 탐지 | 이력 분석·재학습·다수 로봇 관리 |
| 지연 요구 | ms 단위(경성/연성 실시간) | 초~분 단위 허용 |
| 통신 의존 | 없어야 함(단절에도 동작) | 네트워크 필수 |
| 연산 자원 | 제한적(전력·발열·배터리) | 탄력적 확장 |
| 데이터 처리 | 원본 영상 현장 처리 | 이벤트·요약 데이터 위주 |
| 개인정보 | 현장 비식별(마스킹) 가능 | 저장·접근 통제 필요 |
| 장애 영향 | 로봇 1대의 안전 문제 | 관제 기능 저하(로봇은 자율 유지) |

핵심 원칙은 "**안전에 관한 판단은 네트워크를 거치지 않는다**"이다. 클라우드가 끊겨도 로봇은 멈추거나 안전하게 복귀할 수 있어야 하며, 클라우드는 품질을 높이는 역할을 맡는다.

### 실시간·안전 설계 요소
- **제어 루프 분리**: 주행·비상정지 루프는 고우선순위 실시간 태스크로, 영상 AI 추론은 그보다 낮은 우선순위로 분리해 추론 지연이 제어를 막지 않게 한다.
- **페일세이프**(Fail-safe): 센서 이상·통신 두절·배터리 저하 시 감속 → 정지 → 지정 위치 복귀 순으로 상태를 낮춘다.
- **혼잡 공간 대응**: 전통시장은 좁은 통로·불규칙한 인파·노점 물품이 많아 **속도 제한과 보수적 회피 정책**이 필요하다.
- **오탐 관리**: 경보 임계값이 낮으면 관제 인력이 피로해지고, 높으면 사고를 놓친다. 1차 판단은 로봇, 최종 판단은 관제 요원이 맡는 **2단계 확인**이 현실적이다.

### 관련 법·표준
- **개인정보 보호법 제25조의2**: 이동형 영상정보처리기기 운영 기준 — 촬영 사실을 불빛·소리·안내판 등으로 표시해야 한다.
- **지능형 로봇법**: 실외이동로봇 운행안전인증 제도의 근거(인증 로봇의 보도 통행 허용)
- **ISO 13482**: 사람과 공간을 공유하는 개인 돌봄·서비스 로봇의 안전 요구사항(참고 표준)
- **ROS 2 / DDS**: 로봇 소프트웨어 미들웨어. DDS의 QoS(신뢰성·데드라인·수명) 설정으로 토픽별 실시간 요구를 구분한다.

## 3. 기술사 출제 포인트

- 엣지와 클라우드의 처리 분담 기준(지연·통신 의존·연산 자원)
- 인지-판단-제어 계층의 피지컬 AI 시스템 구조
- 통신 단절 시에도 동작하는 자율 안전 설계(페일세이프)
- 실시간 제어 루프와 AI 추론 태스크의 우선순위 분리
- ROS 2·DDS QoS 기반 로봇 미들웨어 구조
- 다수 로봇 통합 관리(Fleet Management)와 OTA 업데이트
- 이동형 영상정보처리기기 개인정보 보호 요건
- 오탐·미탐 균형과 관제 2단계 확인 체계
- 실외이동로봇 운행안전인증 등 제도 요건

## 4. 연결 기출 토픽과 예상 변형

- **엣지 컴퓨팅**: 블로그 통합 기출 분석(`exam_trend_integrated.json`) 기준 **기출 9회**인 시스템구조 빈출 토픽이며, 139회 1교시에도 **엣지 vs 클라우드 컴퓨팅**이 출제됐다. 순찰로봇은 "무엇을 엣지에 두고 무엇을 클라우드로 보낼지"를 설명하기 좋은 사례다.
- **피지컬 AI**: 140회 1교시 **Physical AI와 생성형 AI 비교**, 2교시 **피지컬 AI 논술**이 연달아 출제됐다. 개념 비교에서 한 단계 나아가 **피지컬 AI의 시스템 구조·안전 설계**를 묻는 방향이 자연스러운 변형이다.
- **로봇**: 통합 기출 분석에서 로봇은 기출 6회, 모의 출제 27회로 꾸준히 다뤄지는 키워드다.
- **예상 변형**
  - 1교시: "엣지-클라우드 연속체(Edge-Cloud Continuum)에서 처리 분담 기준을 설명하시오"
  - 1교시: "ROS 2의 구조와 DDS QoS 정책을 설명하시오"
  - 논술: "공공 공간 자율 이동로봇의 시스템 아키텍처를 설계하고, 안전성·개인정보 보호 방안을 제시하시오"

## 5. 답안 구성 예시

**단답형**(1교시, 1페이지)
- 정의: 인지-판단-제어를 로봇 온보드에서 수행하고 관제·학습을 클라우드에서 수행하는 계층형 피지컬 AI 시스템
- 특징 3개: ① 안전 판단의 엣지 자율성 ② 이벤트 중심 클라우드 연계 ③ 페일세이프 상태 전이
- 구성도 키워드: 센서 → 인지 → 판단 → 제어(실시간) / 이벤트 → 관제·재학습 → OTA 배포

**논술형(2~4교시) 목차**
1. 개요: 공공 안전 인력 공백과 피지컬 AI 순찰로봇의 등장
2. 구성/비교: 계층 구성도, 엣지 vs 클라우드 분담 비교표, ROS 2 미들웨어 구조
3. 적용방안: 제어/추론 태스크 분리, 페일세이프 상태 전이, Fleet 관리와 OTA, 현장 비식별 처리
4. 고려사항: 혼잡 공간 주행 안전, 오탐에 따른 관제 피로, 영상 개인정보, 통신 음영 지역
5. 기술사 제언: 실증 단계부터 **안전 판단의 네트워크 비의존**을 설계 원칙으로 못박고, 오탐률·출동 연계 시간을 성과지표로 관리할 것
